# 算法流程与导航策略

本文档说明当前 Agentic-RAG 长期闭环的算法流程和导航选点策略。

## 1. 闭环主流程

```text
episode/subtask
  -> 构建 RetrievalQuery
  -> Habitat RGB-D 多视角环视
  -> 远程 GroundingDINO + MobileSAM + CLIP
  -> 深度反投影得到 pos_3d / pos_2d
  -> 更新 SceneMemory
  -> 检索候选并计算 S_final
  -> room-level planning 或 object-level planning
  -> Habitat navmesh step_to()
  -> 移动后再次观测
  -> 成功确认或 negative feedback
```

## 2. Query 构建

每个 subtask 会转成统一 query，包含：

- `query_label`
- alias labels
- task type
- image-goal 参考图
- language prompt
- target instance / sampled region 等元数据

推荐启用：

```bash
--target-name-map RAANav/AgenticRAG/config/target_name_map_longterm_v1.json
--normalize-target-names
```

## 3. 候选评分

候选来自 SceneMemory 中已有 object tracks。核心融合项包括：

- label / alias 匹配
- remote CLIP text-image similarity
- target instance / sampled region 关系
- 时间衰减
- object stability
- exist probability
- negative feedback
- Agent prior

最终分数近似为：

```text
S_final = w_rag * S_rag + w_agent * S_agent
```

## 4. 当前默认导航策略：room-level planning

默认参数：

```bash
--planning-mode room
```

room-level planning 先聚合候选到 room，再选 room，再选 room 内目标点。

room score 使用：

```text
S_room =
  0.45 * max_object_score
+ 0.20 * mean_top3_object_score
+ 0.15 * target_room_belief
+ 0.10 * exploration_gain
- room_distance_weight * normalized_geodesic_distance
- 0.20 * room_revisit_penalty
- 0.15 * room_switch_penalty
```

优势：

- 减少 object Top-1 在相近候选间来回跳。
- 利用 room-level memory 和负反馈。
- 更适合长期动态家庭环境。

## 5. 消融策略：object-level planning

```bash
--planning-mode object
```

该模式使用 legacy object Top-1：

```text
selected = argmax S_final(object)
```

适合与 room-level planning 对比。

## 6. Approach pose 与防往复

room-level planning 不直接导航到 object center，而是选择 approach pose：

- 优先可导航。
- 避免最近失败区域。
- 避免最近访问点。
- room commitment 防止 `A -> B -> A` 震荡。

## 7. 目标确认

推荐正式评测使用：

```bash
--target-confirmation-mode spatial
--target-confirmation-margin 1.0
```

该模式要求检测到目标且空间位置接近 benchmark 真值，避免只看到同类物体就误报成功。
