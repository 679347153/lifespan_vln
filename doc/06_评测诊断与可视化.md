# 评测诊断与可视化

本文档说明 `run_temporal_habitat_loop` 的诊断输出、HTML 可视化、搜索视频，以及 HTML 页面崩溃时的排查路径。

## 1. 主要指标

- `success_rate`：benchmark 成功率，通常由最终位置到目标真值位置的距离是否小于 `success_radius` 判定。
- `spl`：Success weighted by Path Length，成功率与路径效率的综合指标。
- `found_rate`：subtask 层面成功找到目标的比例。
- `GHR@3 / GHR@5`：候选 top-k 中是否存在接近目标真值位置的候选。
- `candidate_recall_rate`：候选生成阶段是否产生有效候选。
- `avg_final_dist`：最终位置到目标的平均距离。
- `avg_candidate_min_dist`：候选点到目标的最小平均距离。
- `dynamic_memory_accuracy`：动态物体记忆的命中准确性。

## 2. 诊断脚本

```bash
python log_filter.py --run "python -m RAANav.AgenticRAG.benchmark_adapter.diagnose_temporal_run \
  --output-dir benchmark/eval/<run> \
  --write-json benchmark/eval/<run>/diagnosis.json"
```

重点查看：

```text
failure_bucket
perception_found_rate
candidate_recall_rate
ghr5_rate
ghr5_to_found_gap
avg_final_minus_candidate_min_dist
fallback_count
top labels
memory events
negative feedback
```

导航安全层重点查看：

```text
navigation_summary.json
nav_rejected_goals
nav_clipped_goals
avg_snap_distance
max_adjacent_nav_distance
scene_outside_goal_count
nav_reject_reasons
```

其中 `requested_pose` 表示原始候选导航点，`snapped_pose` 表示投影到 navmesh 后的位置，`safe_waypoint` 表示本轮实际允许执行的局部 waypoint。若 `nav_clipped_goals` 较多，说明候选距离较远但已被安全层截断；若 `nav_rejected_goals` 较多，应优先检查候选定位、room representative 或 fallback 是否落在不可达区域。

## 3. HTML 可视化

推荐命令：

```bash
python log_filter.py --run "python -m RAANav.AgenticRAG.benchmark_adapter.visualize_temporal_run \
  --output-dir benchmark/eval/<run> \
  --max-observations 12000 \
  --max-navmesh-contours 12000 \
  --max-navigable-points 1200 \
  --max-layout-objects 400 \
  --max-semantic-regions 120"
```

输出：

```text
benchmark/eval/<run>/visual_debug/index.html
benchmark/eval/<run>/visual_debug/visual_payload.json
```

功能：

- 2D navmesh / region / trajectory / candidates / observations。
- 3D debug 视图。
- Room Memory 树。
- Object room belief 表。
- Candidate rounds 表。
- 阶段性 memory timeline。
- 导航安全点：requested pose、snapped pose、safe waypoint 会用不同颜色标出。

Memory 显示模式：

```text
阶段累计
仅当前增量
最终快照
```

## 4. HTML 崩溃路径分析

HTML 可视化不是重新运行实验，而是把结果目录中的 JSON/JSONL 读入并打包成 `visual_payload.json`，再把 payload 嵌入 `index.html`：

```text
run.jsonl
candidate_traces.jsonl
observation_traces.jsonl
memory_updates.jsonl
scene_memory/*/scene_memory_final.json
scene_geometry/*.json
diagnosis.json 或在线 diagnose()
  -> visual_payload.json
  -> index.html
  -> 浏览器一次性解析并渲染
```

因此 HTML 崩溃通常发生在三类位置：

- Python 生成阶段失败：缺少 `run.jsonl`、JSONL 损坏、结果目录没有写完。
- payload 过大：全量 observations、navmesh contours、candidate path arrays 过多，浏览器解析 JSON 时白屏或卡死。
- 浏览器前端渲染失败：JS 模板与新字段不兼容，或 3D/地图图层一次性绘制太多点。

当前 visualizer 已做保护：

- `candidate_traces.jsonl` 会被压缩，只保留 HTML 需要的字段，不再嵌入完整 `nav_safety.path_points`、`path_resampled_points` 等长数组。
- `observation_traces.jsonl` 默认最多嵌入 `12000` 条。
- `scene_geometry` 默认最多嵌入 `12000` 条 navmesh contour、`1200` 个 navigable points、`400` 个 layout objects。
- `memory_updates.jsonl` 会被压缩为可视化所需的轻量字段。

## 5. HTML 崩溃时的降级命令

如果打开 `index.html` 仍然白屏或浏览器卡死，先用更小 payload 生成：

```bash
python log_filter.py --run "python -m RAANav.AgenticRAG.benchmark_adapter.visualize_temporal_run \
  --output-dir benchmark/eval/<run> \
  --max-observations 3000 \
  --max-navmesh-contours 3000 \
  --max-navigable-points 300 \
  --max-layout-objects 150 \
  --max-semantic-regions 80"
```

如果仍崩溃，继续降级：

```bash
python log_filter.py --run "python -m RAANav.AgenticRAG.benchmark_adapter.visualize_temporal_run \
  --output-dir benchmark/eval/<run> \
  --max-observations 1000 \
  --max-navmesh-contours 1000 \
  --max-navigable-points 100 \
  --max-layout-objects 80 \
  --max-semantic-regions 40"
```

生成后检查 payload 大小：

```bash
python log_filter.py --run "python - <<'PY'
from pathlib import Path
p = Path('benchmark/eval/<run>/visual_debug/visual_payload.json')
print(p, p.stat().st_size / 1024 / 1024, 'MB')
PY"
```

若 `visual_payload.json` 超过几十 MB，浏览器白屏大概率来自 payload 过大，应优先降低上述上限。

## 6. 浏览器侧排查

打开 HTML 后若白屏：

1. 按 `F12` 打开浏览器开发者工具。
2. 查看 Console 是否有 `SyntaxError`、`TypeError` 或 `JSON.parse` 错误。
3. 查看 Network 或 Sources 中 `index.html` 是否完整加载。
4. 若 Console 报字段为空，例如 `Cannot read properties of undefined`，优先检查结果目录是否完整生成。
5. 若页面长时间无响应，优先使用第 5 节的降级命令减少 payload。

## 7. Subtask 级实时搜索视频

运行前指定录制：

```bash
--record-search-video
--video-subtasks "0:0,0:3,<subtask_id>"
--video-output-dir benchmark/eval/<run>/videos
--video-width 1920
--video-height 1080
```

输出：

```text
benchmark/eval/<run>/videos/<episode_id>/<subtask_id>/search.mp4
benchmark/eval/<run>/videos/<episode_id>/<subtask_id>/video_manifest.json
```

视频 Dashboard 内容：

- 左侧主画面：观测阶段默认显示多视角 mosaic，移动阶段显示当前第一视角 RGB。
- 右上地图：显示 navmesh、semantic region、layout objects、trajectory arrows、target、planned pose、top candidates。
- 右中规划面板：显示 planning mode、selected room、selected pose source、selected candidate 和 top-k 候选。
- 右下记忆面板：显示当前 round 的 memory delta、negative feedback 和最近记忆事件。
- 底部 timeline：显示 `PRE_OBSERVE -> PLAN -> MOVE -> POST_OBSERVE -> FEEDBACK -> SUMMARY` 阶段顺序。

默认会开启多视角 mosaic。若需要回到旧式单主视角显示，可显式增加：

```bash
--no-video-include-observation-views
```

注意：视频依赖 `cv2.VideoWriter`，目标运行环境需要安装 OpenCV 并支持 `mp4v`。
