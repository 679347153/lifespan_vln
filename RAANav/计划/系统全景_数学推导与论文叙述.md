## 1. 问题动机与核心贡献

### 1.1 论文研究问题定义

核心目标：机器人所处的环境并非一成不变，环境中的物体会随着人们的使用而被替换、挪动……出现一系列变化，这为我们寻找该物体增加了挑战。
将导航问题降维定义为机器人寻找xxx物体（比如find a chair），那么该领域需要解决机器人长期在一个环境中导航的探索、学习、记忆问题。我们的系统设计目标是：**在动态环境中，构建一个能够长期记忆、持续学习、适应变化的机器人系统**。利用该系统机器人对一个环境记忆学习可以超过一个月，实现对环境、用户习惯的记忆和利用。
实现方式大体思路：
1. 机器人建图之前有Scene Graph和分层语义地图的概念，我们结合AI中RAG的概念，用分层语义地图保存机器人在长期探索获取的信息实现信息查找。每次建图获取的分层场景图并且与之前的内容合并，时间越近的分层语义SG图权重更高，查询物体时结合物体属性（比如后文定义的stability）检索建立的带时间权重合并后的分层语义地图得出一个概率得分；我们解决的核心特点也在于**基于时间序列的场景图合并来完成对环境的量化学习**；
2. 又由于Agent具有先验知识，利用Agent对环境的认知在还没有太多探索结果时做一定补充（我们会将RAG图也输入给他，根据预定提示词他会自主判断房间类型之类的内容），Agent也会对物体可能出现的位置的附近做出一个打分；
3. 对于Agent打分和RAG的结果的概率得分两者的权重逻辑是：随着探索次数增加，Agent的权重降低，从建立的分层语义地图中RAG出的概率得分权重升高；这一创新点核心观点在与，**动态权重融合**，在对新环境的探索初期更依赖Agent的先验认知，而随着探索的深入逐渐过渡到更加信任历史记忆（RAG图）；
4. 其它设计：
    关于GMM概率输出：我们最终利用的不是得出的绝对坐标，而是根据得分得到出该查询物体在各个位置存在的概率地图（使用高斯混合模型实现，即GMM），从而指导机器人探索XX物体经常出现的A、B、C三个位置。

**核心挑战**：
- 环境非静态——物体会被人移动、替换、新增、消失
- 单次建图无法捕获长期变化规律
- 进一步上升到高级语义导航
    注：1. 误区补充：同类物体的多实例问题（如 11 把椅子）不一定需要视觉特征区分：如果场地里面有多个椅子，我的命令仅仅是"chair"，那么任意一把椅子即可，因为这个就是满足的目标，所以地图中可以出现多个符合我们目标的标记
    2. 高级的语义导航比如用户说“我饿了”利用AI Agent的思考将任务降维至普通寻物（“我饿了” → 机器人推理出可能想找微波炉/冰箱 → 导航寻找）需要更复杂的任务拆分和反馈循环。这些等我们加上agent的任务拆分和agent根据反馈重新思考规划的能力后再考虑，目前先让机器人能够根据我们生成的概率地图去寻找目标物体，实现基本的寻物功能验证算法有效性。
- 导航失败后需要动态调整搜索策略（而非重复前往同一错误位置）

### 2.1 双模式运行架构

系统分为两阶段运行：

**深度探索模式（Stage 1）**：全面建图，构建房间边界和完整物体图谱。使用重计算（点云分割、HOV-SG 式双裁剪 CLIP 编码）。产出标记 `source_mode = "deep_exploration"`。

**任务模式（Stage 2）**：执行具体寻物任务。使用轻量感知（mask_only CLIP 编码），边走边增量更新。产出标记 `source_mode = "task_navigation"`。

## 2.B 深度探索模式详述（Stage 1）

### 2.B.1 设计动机

深度探索的目标是在**首次进入环境**时构建尽可能完整的环境语义地图。该地图作为后续所有任务导航的"长期记忆"基础。

### 2.B.2 探索算法：Frontier-based 全覆盖

采用 **Frontier-based exploration**（参考 Yamauchi 1997, BeliefMapNav 2024），而非随机漫走或预定义路径，原因：
- Frontier（已知/未知边界）天然指向信息增益最大的方向
- 保证在有限步数内最大化覆盖率——每步都朝未探索区域前进
- 与占据栅格自然耦合——frontier 直接从栅格边界检测

**具体步骤**（每步循环）：

1. **360° 环视观测**：agent 在当前位置旋转 $n_{views}=4$ 次（每次 90°），每视角同时获取 RGB 和深度图
2. **占据栅格增量更新**：每视角的深度图经 `update_from_habitat_depth()` 反投影到 2D 占据栅格。仅累积高度 $\geq 1.2m$ 的深度点（等价于 HOV-SG 的墙壁密度直方图方法，过滤地面点）
3. **物体检测 + CLIP 编码**：使用 GroundingDINO + MobileSAM 感知管线（见 §2.C）
4. **Frontier 检测与选择**：从占据栅格提取 FREE/UNKNOWN 边界的连通分量。评分标准：距所有已访问位置最远的 frontier（鼓励广度优先探索），同时过滤面积 $< 0.3 m^2$ 的小碎片 frontier
5. **路径规划与行走**：navmesh `pathfinder.find_path()` 或 A* → 路径按 `step_size = 1.0m` 等距重采样 → **teleport 逐步行走**（`move_to_waypoint_teleport()`, navmesh snap 保证不穿墙）
6. **终止条件**：覆盖率 $\geq$ `coverage_target`(95%) / 无 frontier / 达到 `max_steps`(200) / 连续 `stale_threshold`(15) 步无新 free cell

**选择 teleport 而非连续步进的原因**：深度探索阶段环境固定（无动态障碍），目标是最大化覆盖效率。teleport 通过 navmesh snap 保证位置合法性，不受场景 mesh 碰撞检测的过度限制（见 v0.8 根因分析：连续步进的 `agent.act("move_forward")` 在家具密集区域被 mesh 碰撞反复阻挡，导致机器人150步原地不动）。

### 2.B.3 后处理

探索结束后执行以下后处理：

1. **房间分割**：HOV-SG 风格距离变换+分水岭算法（见 §9.9）
2. **Voronoi 拓扑图**：从占据栅格边界提取 Voronoi 图 → 过滤 → 稀疏化 → networkx 图
3. **产出**：`semantic_map.json`（完整物体图谱 + 房间 + CLIP embedding）、`voronoi_nav_graph.json`（拓扑导航图）、占据栅格快照

## 2.C 语义感知获取流程

### 2.C.1 模型选型与理由

| 模型 | 版本/权重 | 用途 | 选型理由 |
|------|----------|------|---------|
| **GroundingDINO** | SwinT_OGC (`groundingdino_swint_ogc.pth`, ~694MB) | 开放词汇目标检测 | 文本引导零样本检测，无需预定义类别集，可检测任意自然语言描述的物体；~2GB VRAM，适合边缘部署 |
| **MobileSAM** | vit_t (`mobile_sam.pt`, ~39MB) | 从 bbox 生成精确的实例分割 mask | 轻量级 SAM 变体，ViT-Tiny 骨干网络，推理速度为原始 SAM 的 50 倍以上；mask 质量接近原版，满足深度反投影精度需求 |
| **CLIP** | `openai/clip-vit-base-patch32` (HuggingFace, 512维) | 物体视觉 embedding + 文本语义匹配 | ViT-B/32 是精度与速度的平衡点；512维向量足够区分室内物体实例；支持零样本跨模态检索；被 HOV-SG、DovSG 等同类工作广泛验证 |
| **Qwen-plus** | DashScope API | LLM Agent 通道：推理物体-房间关联 | 中文/英文双语，推理能力强，API 调用延迟低（~1s）；通过结构化 prompt 实现可控的 JSON 输出 |

```
│   ├─ 结构物: 丢弃 wall/floor/ceiling/door/window   │
│   ├─ BERT碎片: 丢弃 "##helf", "##er" 等子词标签    │
│   └─ 面积: 丢弃 bbox 面积过小的检测                 │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ MobileSAM (实例分割)                               │
│   输入: RGB + bbox → 输出: 二值 mask               │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ 深度反投影 (mask 区域)                              │
│   depth[mask] → 相机坐标 → 旋转矩阵 → 世界坐标     │
│   → pos_3d = median(world_points)                  │
│   → region = 2D convex hull on (x,z) plane         │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ CLIP 视觉编码                                      │
│   mask_only: CLIP(masked_crop) → f ∈ R^512         │
│   full:      0.75·CLIP(masked) + 0.25·CLIP(local)  │
│              → L2 归一化 → f ∈ R^512                │
│   批量: batch_size=32                               │
└──────────────────┬───────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────┐
│ 帧内去重 (dedup_intra_frame)                       │
│   同label + pos_3d距离 < 0.5m → 合并为1个实例       │
│   pos_3d取均值, cfd取最大, clip_emb保留最高cfd       │
└──────────────────┬───────────────────────────────┘
                   ▼
  输出: List[Object] (label, pos_3d, clip_embedding, cfd, ...)
```

### 2.C.3 65类检测标签，将打算构建该stability_prior的数据集（可随着大场景的变化微调）

统一由 `config/stability_priors.yaml` 的 `detect_labels:` 段管理：

覆盖室内主要物体类别，包含家具（chair, table, sofa, bed, shelf, cabinet, desk, ...）、电器（tv, refrigerator, microwave, oven, washing machine, ...）、装饰品（painting, picture, mirror, plant, vase, statue, ...）、生活用品（pillow, cushion, towel, book, bottle, ...）等。从 v0.5 的 42 类扩展到 v0.6 的 65 类，新增 decoration, dining chair, ceiling lamp, carpet, bowl, toy, clothes 等。

每个标签对应一个 **稳定性先验 (stability prior) $\in [0,1]$**：
- 冰箱 `stability = 0.95`：固定不动，高稳定
- 椅子 `stability = 0.70`：可能被移动
- 杯子 `stability = 0.30`：频繁移动，低稳定

稳定性先验在查询评分（§6）中用于时间-稳定性门控 $G_{ts}$，在负向高斯场（§8）中用于调节衰减强度 $\gamma_{neg}$。

## 2.D 任务导航模式详述（Stage 2）

### 2.D.1 输入

- **文本查询** $q$：目标物体的自然语言描述（如 "microwave"）
- **预建地图**：Stage 1 产出的 `semantic_map.json`（加载到 `floors_history`）
- **拓扑图**：`voronoi_nav_graph.json`（可选，加速跨房间路径规划）
- **3D 场景**：Habitat-sim 加载的场景，实时获取 RGB+depth 观测

### 2.D.2 初始化

1. 加载预建地图 → `floors_history`（含所有物体的 label, pos_3d, clip_embedding, ...）
2. 构建活动占据栅格：`OccupancyGrid.from_navmesh_fast()` 或 `from_agent_position()`
3. 初始化导航组件：`HabitatAgent`（连续步进模式）、`GridAStarPlanner`、`VirtualClock`、`NegativeGaussianField`
4. 加载感知器：GroundingDINO + MobileSAM（65 类标签，阈值 0.40/0.35）
5. 初始化 Agent 通道：`RScoreAgent(Qwen-plus)`
6. 强制执行一次 GMM 查询 → 确保 step 1 就有概率场引导

### 2.D.3 主循环（每步详述）

```
for micro_step in range(max_steps):
    ┌──────────────────────────────────────────────────┐
    │ STEP 1: 观测与感知                                │
    │   360°环视 (4×90°):                               │
    │     每视角: RGB → GroundingDINO (65类, 0.40/0.35)  │
    │     → MobileSAM mask → 深度反投影 pos_3d           │
    │     → CLIP 编码 (mask_only, 512维)                 │
    │     + 同时: depth → OccupancyGrid 栅格增量更新     │
    │   帧内去重 → List[Object]                          │
    │                                                    │
    │   ★ 目标检测: 若任一检测的 label 匹配 target       │
    │     → target_found = True → 停止                   │
    └──────────────────┬───────────────────────────────┘
                       ▼
    ┌──────────────────────────────────────────────────┐
    │ STEP 2: 地图增量更新                               │
    │   构建 floors_now (当前观测物体)                    │
    │   → run_merge(floors_now, floors_history, cfg)     │
    │     ├─ CLIP双模式匹配 (§5.1): 跨标签合并           │
    │     ├─ EMA 更新: pos_3d, cfd, clip_embedding       │
    │     ├─ exist_prob: 被观测→恢复, 未观测→衰减         │
    │     └─ R_objs 共现关系更新                          │
    │   VirtualClock.step() 推进虚拟时间                  │
    └──────────────────┬───────────────────────────────┘
                       ▼
    ┌──────────────────────────────────────────────────┐
    │ STEP 3: GMM 概率场查询 (每 query_interval 步)      │
    │   a. CLIP 检索: cos(f_q, f_i) ≥ 0.85              │
    │      → 候选物体 [(obj_id, cosine_score)]            │
    │   b. GMM 评分: S_self(i) × G_ts(i)                 │
    │      + S_robj (共现关系增强)                         │
    │   c. Agent 通道: Qwen-plus LLM 推理                 │
    │      输入: RAG候选摘要, 房间分布, 共现列表           │
    │      输出: 房间级先验 P(room|q), 节点补充分          │
    │   d. 融合: S = w_rag·S_rag + w_agent·S_agent        │
    │      w_agent(n) = max(0.15, exp(-0.35n))            │
    │   e. 概率场: top-20候选 → 2D高斯核叠加              │
    │      prob(x,y) = Σ A_i · exp(-(dist²)/(2σ²))       │
    └──────────────────┬───────────────────────────────┘
                       ▼
    ┌──────────────────────────────────────────────────┐
    │ STEP 4: 假阴性检测 + 负向高斯注入                   │
    │   对每个监视物体:                                    │
    │     距离 < 3m 但连续2步未检测到 → 注入负核           │
    │     α = 0.5×(1-γ_neg), σ = σ_base×2.0              │
    │     半衰期 10步 → 自动消退                          │
    └──────────────────┬───────────────────────────────┘
                       ▼
    ┌──────────────────────────────────────────────────┐
    │ STEP 5: 三层导航决策                                │
    │   Layer 1: 负向高斯修正 prob_corrected              │
    │   Layer 2: 访问密度惩罚 V(x,y)                     │
    │   Layer 3: Flatness判定                             │
    │     prob_max/prob_mean < 3.0 → Frontier模式         │
    │     否则 → GMM引导模式                              │
    │     无概率场 → Frontier回退                         │
    │   → 目标点 (x, z)                                   │
    └──────────────────┬───────────────────────────────┘
                       ▼
    ┌──────────────────────────────────────────────────┐
    │ STEP 6: 路径规划 + 行走                              │
    │   路径: Voronoi拓扑 → A*栅格 → navmesh (三级回退)   │
    │   行走: 连续步进 move_to_waypoint()                  │
    │     ├─ turn + agent.act("move_forward") 序列        │
    │     ├─ 碰撞时尝试 ±15°/±30°/±45° 偏转绕行          │
    │     ├─ 每waypoint前 check_collision_ahead()         │
    │     └─ StuckDetector (5步窗口, 0.5m阈值) → 恢复     │
    │   每步重复 STEP 1-2 (边走边感知+更新)                │
    └──────────────────┬───────────────────────────────┘
                       ▼
    ┌──────────────────────────────────────────────────┐
    │ STEP 7: 多视点调查 (到达GMM目标后)                   │
    │   在概率峰值周围 1.5m 处生成 3 个观测视点            │
    │   每视点 360°环视 → 增量更新                         │
    │   从多角度覆盖目标区域, 避免单方向遮挡假阴性          │
    └──────────────────────────────────────────────────┘
```

### 2.D.4 输出

- `target_found`：是否成功找到目标
- `nav_result.json`：每步日志（位置、观测物体、GMM评分、导航目标）
- `map_final.json`：经任务模式增量更新后的终态地图

## 3. 数据模型：时序分层语义图

### 3.1 三层结构

每次探索生成一张分层场景图 $G_t = (V_t, E_t)$：

```
Floor
  └── Room    (room_id, region_polygon)
       └── Object (obj_id, label, clip_embedding, pos_3d, ...)
```

### 3.2 物体节点定义（Object Node）

每个物体节点 $o_i$ 包含的完整字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `obj_id` | str | 全局稳定唯一标识 |
| `label` | str | 语义标签（如 "chair"） |
| `clip_embedding` | float[512] | CLIP 视觉特征向量 |
| `pos_3d` | float[3] | 3D 世界坐标 $(x, y, z)$ |
| `pos_2d` | dict | 俯视图坐标 $\{x, y\}$ |
| `region` | Polygon | 2D 边界多边形 |
| `cfd` | float | 检测置信度（EMA 融合） |
| `stability` | float $\in [0,1]$ | 动态稳定性先验（由 Agent 赋予） |
| `N` | int | 累计观测次数 |
| `exist_prob` | float $\in [0,1]$ | 当前存在概率 |
| `last_update_time` | ISO-8601 | 最后更新时间戳 |
| `room_id` | str | 所属房间 |
| `R_objs` | dict | 共现关系映射 |
| `cooccur_stats` | dict | 共现统计（正/负） |

### 3.3 共现关系（R_objs）

对于物体 $o_i$，其共现关系记录了与哪些邻近物体一同出现：

```python
R_objs[neighbor_obj_id] = {
    "Nt": int,     # 邻居的总观测次数
    "Nr": int,     # 与 o_i 的共现次数
    "Rcfd": float  # 共现置信度 ∈ [0,1]
}
```

共现置信度的物理含义：$Nr/Nt$ 的加权平滑版本，表示"每次观测到邻居时，有多大概率同时看到 $o_i$"。

## 4. 感知前端：检测、编码与帧内去重

### 4.1 检测流水线

每步导航执行 $n_{views}$ 次环视（默认 4 次×90°=360°），每次：

1. **GroundingDINO**：开放词汇检测，输出 $\{(bbox_{xyxy}, label, cfd)\}$
   - 检测标签：65 类室内物体（config-driven，从 `stability_priors.yaml` 的 `detect_labels:` 段加载）
   - 阈值：任务模式 box=0.40 / text=0.35；探索模式 box=0.35 / text=0.30
2. **MobileSAM**：从 bbox 生成实例掩码 $mask$
3. **白名单过滤**：仅保留 `detect_labels` 中的标签
4. **结构物过滤**：丢弃 wall / floor / ceiling / door / window 等结构类别
5. **BERT 碎片过滤**：丢弃 `label.startswith("##")` 或 `len(label) ≤ 1` 的噪声检测
6. **面积过滤**：丢弃 bbox 面积过小的检测（min area ratio）
7. **CLIP 视觉编码**：为每个检测计算 512 维 CLIP embedding

> **v0.6 变更**：检测标签从 42 类硬编码扩展为 65 类 config-driven，统一由 `_load_detect_labels(cfg)` 加载，新增 decoration、dining chair、ceiling lamp、carpet、bowl、book、toy、clothes、statue、rack、toaster、coffee machine 等类别。阈值降低以提高召回率。

### 4.2 CLIP 视觉编码

参考 HOV-SG 和 DovSG 的双裁剪策略，从 RGB 图像中为每个检测结果提取视觉特征：

#### 裁剪策略

给定检测框 $bbox = (x_1, y_1, x_2, y_2)$ 和实例掩码 $mask$，加 $p$ 像素 padding（默认 $p=20$）后：

- **Local crop**：$rgb[y_1{-}p : y_2{+}p,\; x_1{-}p : x_2{+}p]$（包含上下文的局部裁剪）
- **Masked crop**：与 local crop 同区域，但掩码外像素置零（仅保留目标实例）

#### 编码模式

**Mask-only 模式**（轻量，任务模式默认）：
$$
f_i = \text{CLIP}_{image}(\text{masked\_crop}_i) \quad \in \mathbb{R}^{512}
$$

**Full 模式**（高质量，深度探索推荐）：
$$
f_i = w_m \cdot \text{CLIP}_{image}(\text{masked\_crop}_i) + (1 - w_m) \cdot \text{CLIP}_{image}(\text{local\_crop}_i)
$$
$$
f_i \leftarrow \frac{f_i}{\|f_i\|_2}
$$

其中 $w_m = 0.75$（masked weight，参考 DovSG）。

**原理**：masked crop 聚焦于物体自身外观（消除背景干扰），local crop 提供空间上下文信息（周围环境线索）。加权融合兼顾两者。

**批量编码**：所有裁剪图像以 batch_size=32 送入 CLIP 编码器，一次性计算。

### 4.3 帧内去重（Intra-frame Deduplication） | 会不会导致误删+实际运行不会走每一步进行360度环视

**问题**：同一步的 4 个视角可能检测到同一物体，产生 4 个重复项。

**算法**：

1. 按 $label$ 分组
2. 组内按 $cfd$ 降序
3. 贪心聚类：如果新物体与任一现有聚类中心的 $pos\_3d$ 欧氏距离 $< d_{dedup}$（默认 0.5m），则合并
4. 合并策略：
   - $pos\_3d$ 取均值
   - $cfd$ 取最大值
   - $clip\_embedding$ 保留最高 $cfd$ 的版本

$$
d(o_a, o_b) = \|pos\_3d_a - pos\_3d_b\|_2 < d_{dedup}
$$

**效果**：E2E 测试中，4 个视角的同一物体从 4 个实例减少为 1 个。

### 4.4 房间分配（替代 R0 硬编码）

**问题**：GroundingDINO 检测的物体没有房间归属信息。之前硬编码 `room_id="R0"` 导致所有检测物体只能与 R0 的 53 个预建物体匹配，而 R1-R9 的 209 个物体永远无法被匹配，造成严重膨胀。

**解决方案**：$pos\_3d$ 最近邻分配。

对每个新检测物体 $o_{new}$，在所有历史物体 $\{o_{hist}^{(k)}\}$ 中找到最近邻：

$$
k^* = \arg\min_k \|pos\_3d_{new} - pos\_3d_{hist}^{(k)}\|_2
$$

$$
room\_id_{new} = \begin{cases}
room\_id_{hist}^{(k^*)} & \text{if } \|pos\_3d_{new} - pos\_3d_{hist}^{(k^*)}\|_2 \leq d_{max} \\
\text{"R0"} & \text{otherwise}
\end{cases}
$$

其中 $d_{max} = 5.0$ m。

**效果**：R0 从 353 降至 91 个物体，其余分布到正确的 R1-R9。

### 4.5 DAAAM 真实传感器前端（v0.9 新增）

仿真中使用 GroundingDINO+MobileSAM 作为检测前端。为实现真实机器人部署，系统增加了基于 DAAAM 的高帧率实例分割追踪前端作为可替换模块。

**设计原则**：DAAAM 被视为"实时物体实例传感器"，仅负责输出 $(track\_id, pos\_3d)$ 元组。Spark-DSG 和 Hydra 后端被完全移除（它们依赖 ROS2 colcon 工作空间），替换为轻量的 JSON 通信载体。

**DAAAM 前端流水线**：
$$
\text{RGB-D frame} \xrightarrow{\text{FastSAM}} \text{dets, masks} \xrightarrow{\text{BotSort}} track\_id \xrightarrow{\text{unproject + PoseProvider}} pos\_3d_{world}
$$

**PoseProvider 模块化设计**（关键抽象）：

2D 像素 $(u,v)$ 结合深度 $d$ 和相机内参 $K$ 反投影到 3D 相机坐标：
$$
\mathbf{p}_{cam} = \begin{bmatrix} (u - c_x) \cdot d / f_x \\ (v - c_y) \cdot d / f_y \\ d \end{bmatrix}
$$

世界坐标变换通过可插拔的 PoseProvider 接口完成：
$$
\mathbf{p}_{world} = \text{PoseProvider.camera\_to\_world}(\mathbf{p}_{cam}, t)
$$

| 实现 | 场景 | 数据源 |
|------|------|--------|
| `DatasetPoseProvider` | 离线回放 | `pose/poses.txt`（从 rosbag `/odom` 导出） |
| `IdentityPoseProvider` | 无 pose 退化 | $\mathbf{p}_{world} = \mathbf{p}_{cam}$ |
| `ROSTFPoseProvider`（未来） | 在线部署 | ROS `/tf` 树实时查询 |

**DAAAM→RAANav Bridge**：
离线回放产出的 `summary.json`（$(track\_id, pos\_3d_{world})$）通过桥接脚本转换为 RAANav 兼容的 `semantic_map.json`（Floor→Room→Object），随后直接驱动 GMM 概率场。端到端数据流：
```
rosbag → bag_to_image_sequence.py → ImageSequenceDataset
  → run_frontend_only_pipeline.py → summary.json
  → daaam_to_raanav_map.py → semantic_map.json + GMM heatmap
```

#### 4.5.2 CLIP 零样本语义标注（v0.9.1 新增，替代 GroundingDINO）

**动机**：GroundingDINO 需要 GPU 推理且输出的标签集受限于其训练数据。DAAAM 的架构启发是：将快速类无关分割（FastSAM）与慢速语义标注（CLIP/VLM）解耦。

**CLIP 零样本分类器设计**（`clip_labeler.py`）：

从 DAAAM 的 `CLIPHandler`（`utils/embedding.py`）学习而来，使用 `open_clip` 库加载 ViT-B-16，预计算 53 个室内类别标签的文本嵌入：

$$
\mathbf{t}_j = \frac{\text{CLIP}_{\text{text}}(\text{“a photo of a ”} + \text{label}_j)}{\|\text{CLIP}_{\text{text}}(\ldots)\|_2}, \quad j \in \{1, \ldots, 53\}
$$

对每个 FastSAM 掩码裁剪图像 $I_{\text{crop}}$，计算图像嵌入并通过温度缩放的 softmax 获得标签概率：

$$
\mathbf{f}_i = \frac{\text{CLIP}_{\text{image}}(I_{\text{crop},i})}{\|\text{CLIP}_{\text{image}}(I_{\text{crop},i})\|_2}, \quad
P(\text{label}_j | \text{crop}_i) = \text{softmax}\left(\frac{\mathbf{f}_i \cdot \mathbf{t}_j}{\tau}\right)
$$

其中温度 $\tau = 0.5$ 用于锐化分布。53 个标签通过别名映射去重（如 couch→sofa, fridge→refrigerator）。

**后处理标注管线**（`label_tracks_posthoc.py`）：

遵循 DAAAM 的任务驱动设计 —— 快速前端（6.9fps 分段+追踪）与慢速语义标注解耦：

```
FastSAM + BotSort (6.9fps, 全帧)
  → summary.json (track_id, pos_3d, bbox, mask_area)
  → label_tracks_posthoc.py (offline/post-hoc)
    → 对每个 track 选最大 mask 面积帧
    → CLIP 零样本分类
    → 写入 label + label_confidence + clip_embedding
  → labeled_summary.json
```

这一设计与 DAAAM 的 `AssignmentService → GroundingService` 流水线同构：`label_tracks_posthoc` 相当于一个极简的、无 LLM 的 GroundingService 替代。

**验证结果**（apartment.bag, 100 tracks）：

## 5. 图融合：增量匹配与节点状态更新

### 5.1 双模式匹配（核心创新 C2）

匹配分为两种模式，根据 CLIP embedding 可用性**自动切换**：

#### 模式 A：CLIP 模式（双方均有 clip_embedding）

**搜索范围**：全部历史物体（不限 label）——这是与传统方法的关键区别。

**第一步：CLIP 前置过滤**
$$
\cos(f_{now}, f_{hist}) \geq \tau_{clip} \quad (\tau_{clip} = 0.65)
$$

不满足则直接跳过该候选。

**第二步：联合匹配评分**

$$
S_{match}(i,j) = \eta_1 \cdot IoU_{2D}(i,j) + \eta_2 \cdot \cos(f_i, f_j) - \eta_3 \cdot \hat{d}(i,j)
$$

其中：
- $IoU_{2D}(i,j) = \frac{|R_i \cap R_j|}{|R_i \cup R_j|}$：2D 边界多边形的交并比
- $\cos(f_i, f_j)$：CLIP 视觉特征的余弦相似度
- $\hat{d}(i,j) = \min\left(\frac{\|pos\_3d_i - pos\_3d_j\|_2}{d_{norm}}, 1.0\right)$：归一化欧氏距离

**第三步：阈值判定**

若 $S_{match} > \tau_{match}$（默认 0.55），视为同一实体。

**参数**：$\eta_1 = 0.4,\; \eta_2 = 0.4,\; \eta_3 = 0.2,\; d_{norm} = 3.0$ m

**原理分析**：
- 传统方法（如 osmAG-LLM）使用 label 严格匹配，当 GroundingDINO 输出 "pillow" 而预建地图使用 "pillow cushion" 时，无法匹配 → 产生重复节点
- CLIP 模式下，"pillow" 与 "pillow cushion" 的 CLIP cosine 约 0.97，远超 0.65 阈值 → 成功跨标签匹配
- 同时，CLIP 可防止误合并：两个不同类别物体即使 label 相近（如 "shelf" vs "shelf bookshelf cabinet"），CLIP 外观差异会通过 $\eta_2$ 项正确区分

#### 模式 B：轻量模式（任一方无 clip_embedding）

**搜索范围**：仅同 label 候选。

**条件**（全部满足）：
1. $label_{now} = label_{hist}$
2. $\|pos\_3d\|_2 < d_{threshold}$ (1.0m) **或** $IoU_{2D} \geq \tau_{iou}^{loose}$ (0.3)
3. 若一方有 CLIP embedding，需 $\cos(f_i, f_j) \geq \tau_{clip}^{reject}$ (0.4)

**选择标准**：距离最近的满足条件的候选。

### 5.2 节点状态更新（匹配成功时）

当 $o_{now}$ 成功匹配到 $o_{hist}$ 后，进行以下更新：

#### 5.2.1 观测计数累加

$$
N_{new} = N_{hist} + N_{now}
$$

#### 5.2.2 置信度 EMA 更新

$$
cfd_{new} = \frac{(\epsilon_{cfd}^{N_{hist}} - \epsilon_{cfd}^{N_{new}}) \cdot cfd_{hist} + (1 - \epsilon_{cfd}) \cdot cfd_{now}}{1 - \epsilon_{cfd}^{N_{new}}}
$$

其中 $\epsilon_{cfd} = 0.75$ 为记忆率。

**推导**：这是指数加权移动平均（EMA）的精确公式。假设历史 $cfd_{hist}$ 是前 $N_{hist}$ 次观测的 EMA 结果，当前 $cfd_{now}$ 是第 $N_{new}$ 次观测，则新的 EMA 结果即上式。$\epsilon_{cfd}$ 越高，历史权重越大（记忆越持久）；越低，当前观测权重越大（反应越灵敏）。

同一公式也用于 $Rcfd$ 和 $clip\_embedding$ 的更新，只是 $\epsilon$ 参数分别为 $\epsilon_{Rcfd} = 0.75$ 和 $\epsilon_{clip} = 0.75$。

#### 5.2.3 位置 EMA 更新

$$
pos\_3d_{new} = \alpha \cdot pos\_3d_{now} + (1 - \alpha) \cdot pos\_3d_{hist}
$$

其中 $\alpha$ 取决于运行模式：
- 深度探索模式：$\alpha_{deep} = 0.5$（更信任高质量观测）
- 任务模式：$\alpha_{task} = 0.3$（标准增量更新）

**原理**：位置不像 cfd 那样需要累积统计，而是需要反映"最新最可靠的估计"。EMA 平衡了"最新观测"和"历史积累"——如果物体被轻微移动，EMA 会逐步追踪新位置。

#### 5.2.4 存在概率恢复（被观测到=仍然存在）

$$
exist\_prob_{new} = w_{recover} \cdot exist\_prob_{now} + (1 - w_{recover}) \cdot exist\_prob_{hist}
$$

$w_{recover} = 0.75$。被再次观测到的物体，其存在概率向 1.0 恢复。

#### 5.2.5 CLIP Embedding EMA 融合

$$
clip\_emb_{new} = \frac{(\epsilon_{clip}^{N_{hist}} - \epsilon_{clip}^{N_{new}}) \cdot clip\_emb_{hist} + (1 - \epsilon_{clip}) \cdot clip\_emb_{now}}{1 - \epsilon_{clip}^{N_{new}}}
$$

**原理**：物体外观可能因光照、角度等因素在不同观测中有差异。EMA 融合使 embedding 逐渐趋近物体的"平均外观表示"，提升匹配鲁棒性。

### 5.3 未匹配处理

#### 历史物体未被当前观测覆盖（缺失）

$$
exist\_prob_{new} = exist\_prob_{hist} \times \gamma_{miss}
$$

$\gamma_{miss} = 0.80$（每轮保留 80%）。多轮连续缺失后呈指数衰减：

$$
exist\_prob_t = exist\_prob_0 \times \gamma_{miss}^{t}
$$

#### $R\_objs$ 中的缺失关系衰减

对于历史中存在但当前未观测到的共现物体：

$$
Rcfd_{new} = \text{EMA}(\epsilon_{Rcfd},\; Rcfd_{hist},\; 0,\; N_{total},\; N_{hist})
$$

即以 $Rcfd_{now} = 0$ 参与 EMA，使共现置信度逐步衰减。

### 5.4 身份锚定原则

匹配成功时，**继承历史物体的 label、room_id、obj_id**：

```python
obj_new.label = matching_obj_history.label      # 保持历史标签
obj_new.room_id = matching_obj_history.room_id  # 保持历史房间
obj_new.obj_id = matching_obj_history.obj_id    # 保持历史 ID
```

**原理**：预建地图的标签经过人工校验或高质量流程生成，比在线检测的标签更可靠。保持 ID 稳定性对长期追踪至关重要。

## 6. 查询评分模型：RAG + Agent 双通道

设查询文本向量为 $f_q$（CLIP 编码），候选节点为 $o_i$。

### 6.1 RAG 通道评分

#### 6.1.1 CLIP 语义检索

使用运行时 CLIP 索引对地图中所有物体进行余弦相似度搜索：

$$
R_{sim}(i) = \cos(f_q, f_i) = \frac{f_q \cdot f_i}{\|f_q\| \cdot \|f_i\|}
$$

阈值过滤：$R_{sim}(i) \geq 0.85$ 才进入后续评分。

**动态索引**：每次 GMM 查询时，从 `floors_history` 内存中动态构建 CLIP 索引（而非使用启动时的静态索引），确保新增物体能被检索到。

#### 6.1.2 物体自身评分

$$
S_{self}(i) = \sigma_k(N_i) \times stability_i \times cfd_i
$$

其中 Sigmoid 激活函数：

$$
\sigma_k(N) = \frac{1}{1 + e^{-k(N - N_0)}}
$$

$k = 1.0$, $N_0 = 5.0$。

**物理含义**：观测次数越多（$N > 5$），Sigmoid 越接近 1，代表"我们对这个物体的认知越充分"。乘以 $stability$ 和 $cfd$ 使高稳定、高置信的物体获得更高评分。

#### 6.1.3 相关物体评分

对于 CLIP 命中物体 $o_i$ 的每个共现邻居 $o_j$：

**关系增强项**：
$$
R_{enhance}(j) = e^{\lambda \cdot \frac{Nr_j}{N_j} + Rcfd_j}
$$

其中 $\lambda = 0.5$（Nr_lambda_param）。

**Log 压缩归一化**：
$$
\hat{R}_{enhance}(j) = \frac{\ln(1 + R_{enhance}(j))}{\ln(1 + e^{\lambda + 1})}
$$

**自适应权重**（随总观测次数 $N_{total}$ 变化）：

$$
\omega_2 = \sigma_k(N_{total}), \quad \omega_1 = 1 - \omega_2
$$

**融合评分**：
$$
S_{robj}(j) = (\omega_1 \cdot \hat{Rscore}_j + \omega_2 \cdot \hat{R}_{enhance}(j)) \times stability_j \times exist\_prob_j
$$

**原理**：
- 早期（$N$ 小）：$\omega_1 \approx 1$，主要靠 $Rscore$（CLIP检索分数）
- 后期（$N$ 大）：$\omega_2 \to 1$，主要靠共现关系增强
- 这实现了"探索越多，越信任基于经验的关联推理"的渐进策略

#### 6.1.4 时间-稳定性指数门控

$$
G_{ts}(i) = \exp\left(-\frac{\lambda \cdot \Delta T_i}{1 + \kappa \cdot stability_i}\right)
$$

**物理含义**：
- $\Delta T_i$ 越大（越久没被观测），$G_{ts}$ 越小 → 整体信任度下降
- $stability_i$ 越高（物体越稳定），分母越大 → 衰减越慢 → "冰箱比杯子更抗遗忘"

**示例**：设 $\lambda \Delta T = 0.5$, $\kappa = 1.0$
- 杯子（$stability = 0.2$）：$G_{ts} = e^{-0.5/1.2} \approx 0.66$
- 冰箱（$stability = 0.9$）：$G_{ts} = e^{-0.5/1.9} \approx 0.77$

#### 6.1.5 RAG 总分

$$
S_{base}(i) = \beta_1 \hat{R}_{sim}(i) + \beta_2 \hat{R}_{cfd}(i)
$$

$$
S_{rag}(i) = S_{base}(i) \cdot G_{ts}(i)
$$

$\beta_1 = 0.65$, $\beta_2 = 0.35$。

### 6.2 Agent 通道评分（已实现 ✅）

Agent（大语言模型 Qwen-plus）输入当前 RAG 候选摘要（房间分布、共现物体列表、近期变化），通过 `score_for_navigation()` 输出：

- 房间级先验 $P_{agent}(room \mid q)$
- 节点/区域级补充分 $S_{agent}(i)$

**实现**：`GMM_map_Create/agent_Rscore.py` 中 `RScoreAgent.score_for_navigation()`。

> **当前状态**：✅ 已实现并接入闭环。使用 DashScope API 调用 Qwen-plus，配置 `nav_enabled: true`。

### 6.3 动态融合权重（已实现 ✅）

$$
w_{agent}(n) = \max(w_{min}, \exp(-kn))
$$

$$
w_{rag}(n) = 1 - w_{agent}(n)
$$

$$
S(i) = w_{rag}(n) \cdot S_{rag}(i) + w_{agent}(n) \cdot S_{agent}(i)
$$

其中 $n$ 为累计探索轮次，$k = 0.35$，$w_{min} = 0.15$。

**物理含义**：
- $n = 0$：$w_{agent} \approx 1.0$，完全依赖大模型常识
- $n = 3$：$w_{agent} \approx 0.50$，两者平衡
- $n \gg k$：$w_{agent} \to 0.15$，主要依赖历史记忆，但保留 15% 常识修正

> **当前状态**：✅ 已实现。配置 `nav_fusion_k: 0.35`，`nav_fusion_w_min: 0.15`，`nav_query_interval: 2`。

## 7. 空间概率化：GMM 概率场

### 7.1 概率场构建

取评分前 $N$ 高的候选节点 $\{(\mu_i, S(i))\}_{i=1}^{N}$（默认 $N = 20$），在占据栅格上叠加高斯核：

$$
P(x,y \mid q) = \sum_{i=1}^{N} A_i \cdot \exp\left(-\frac{(x - \mu_{i,x})^2 + (y - \mu_{i,y})^2}{2\sigma_{px}^2}\right)
$$

其中：
- $A_i = S(i) \times \alpha_{amplify}$：放大后的幅值（$\alpha_{amplify} = 3.0$）
- $\sigma_{px} = \sigma_{base} / resolution$：高斯核标准差（像素单位）
- $\sigma_{base} = 1.0$ m（世界坐标标准差）

**关键设计决策：不做全局归一化**。

> **为什么不归一化？** 早期版本使用 `prob /= sum(prob)` 归一化到概率和为 1。当候选物体数量较多时，每个高斯核的绝对值极小（如 $0.000342$），导致 $prob_{max} / prob_{mean}$ 始终 $< 3.0$，系统**永远认为概率场退化**，从不使用 GMM 引导，而始终回退到 Frontier 模式。去除归一化后，$prob_{max}$ 保持在合理范围（$\sim 0.2\text{-}0.4$），flatness 判定才有意义。

### 7.2 可通行约束（导航层面处理，v0.7 修正）

> **v0.7 重要变更**：移除了概率场层面的 $M_{free}$ 约束。
>
> **原因**：物体（如桌子、椅子、冰箱）在占据栅格上本身就位于 OCCUPIED cell，对概率场施加 $P(x,y) \leftarrow P(x,y) \times M_{free}(x,y)$ 会将物体所在位置的概率清零，导致 GMM 引导完全失效。
>
> **修正做法**：概率场不受 free_mask 约束，仅作为引导信号。可通行约束下推到导航策略层面——在 `frontier_exploration_step()` 中：
> $$score[grid \neq FREE \land grid \neq UNKNOWN] = -\infty$$
> 即**导航目标只选可通行 cell**，但概率场保留了物体位置附近的高概率信号以引导方向。

### 7.3 高斯核实现细节

为避免全图计算，每个高斯核只在以 $\mu_i$ 为中心、$3\sigma_{px}$ 为半径的窗口内计算：

```python
win = ceil(3 × σ_px)
r0, r1 = max(0, r - win), min(H, r + win + 1)
c0, c1 = max(0, c - win), min(W, c + win + 1)
```

在 $3\sigma$ 处高斯值衰减为峰值的 $e^{-4.5} \approx 1.1\%$，截断误差可忽略。

### 7.4 动态栅格参数

概率场**必须**使用当前活动的占据栅格元数据（分辨率、原点），而非启动时加载的旧栅格数据。这确保了深度累积障碍物被正确反映。

## 8. 负向高斯场：机器人"记仇"机制（核心创新 C3）

### 8.1 动机

当机器人导航到 GMM 高概率区域后**未检测到目标物体**，系统应当：
1. **主动降权**该区域（而非仅仅"停止加权"）
2. 为下一轮搜索提供**排斥信号**（"已验证不在这里"）
3. 排斥信号应随时间**自然消退**（物体可能被放回）

### 8.2 触发条件

对于监视列表中的每个目标相关物体 $o_w$：

1. **距离判定**（视锥覆盖的简化代理）：
$$
\|pos_{agent} - pos_{o_w}\|_2 < r_{trigger} \quad (r_{trigger} = 3.0 \text{ m})
$$

2. **连续失败**：连续 $miss\_threshold = 2$ 步未检测到 → 触发注入

### 8.3 负向核参数

**衰减系数（与物体稳定性关联）**：
$$
\gamma_{neg} = 0.1 + 0.25 \times (1 - stability)
$$

**负向核权重**：
$$
\alpha = 0.5 \times (1 - \gamma_{neg})
$$

**负向核方差**：
$$
\sigma_{neg} = \sigma_{base} \times r_{neg}, \quad r_{neg} = 2.0
$$

**物理含义**：
- 高稳定物体（冰箱，$stability = 0.95$）：$\gamma_{neg} = 0.11$，$\alpha = 0.44$ → **强惩罚**（冰箱不在预期位置，高概率是地图错误或重大变化）
- 低稳定物体（杯子，$stability = 0.3$）：$\gamma_{neg} = 0.28$，$\alpha = 0.36$ → **弱惩罚**（杯子容易被拿走，一次未找到不必过度反应）
- 负向核方差是正向核的 2 倍 → 影响范围更大 → "这片区域及其周边都不太可能有"

### 8.4 负向核叠加

$$
P'(x,y) = \max\left(0,\; P_{original}(x,y) - \sum_{j \in \text{neg}} \alpha_j^{eff} \cdot \mathcal{N}\left((x,y);\; \mu_j,\; \sigma_{neg,j}^2 I\right)\right)
$$

**截断非负 + 归一化**：
$$
P_{final}(x,y) = \frac{P'(x,y)}{\sum_{x,y} P'(x,y) + \epsilon}
$$

### 8.5 时间衰减（核心创新：负核不是永久的）

每个负向核的有效权重随步数衰减：

$$
\alpha_j^{eff}(t) = \alpha_j \times \exp\left(-\frac{\ln 2}{T_{half}} \times age_j\right)
$$

其中 $T_{half} = 10$ 步（半衰期），$age_j = t_{current} - t_{inject}$。

**原理**：
- 10 步后，负核强度衰减到一半
- 20 步后，衰减到 25%
- 30 步后，衰减到 12.5%

这避免了"过度记仇"——物体可能被暂时遮挡（而非真正不在），或者在后续时间步被放回原位。负核的自动消退让系统保持对动态变化的开放性。

> **对比**：规范中原始设计是负核永久存在。实现中发现这导致 agent 在验证失败后"永远不回头"，丧失了适应动态环境的能力。

### 8.6 完整的负向高斯场整合公式

$$
P(x,y \mid q) = \left[\sum_{i=1}^{N} \pi_i \cdot \mathcal{N}\left((x,y);\; \mu_i,\; \Sigma_i\right) + \sum_{j=1}^{M} \pi_j^{neg}(t) \cdot \mathcal{N}\left((x,y);\; \mu_j,\; \Sigma_j^{neg}\right)\right]_{clipped}
$$

其中 $[\cdot]_{clipped}$ 表示截断负值为 0，$\pi_j^{neg}(t) < 0$ 为带时间衰减的负权重。

## 9. 导航决策：三层探索策略（核心创新 C4）

### 9.1 概述

在每个宏步（macro step），系统通过三层决策确定下一个导航目标：

```
Layer 1: 负向高斯修正
    ↓
Layer 2: 访问密度惩罚
    ↓
Layer 3: Flatness 判定 → GMM 引导 / Frontier 回退
    ↓
导航目标点 (x, z)
```

### 9.2 Layer 1：负向高斯修正

$$
P_{corrected}(x,y) = \text{NegField.apply}(P_{base}, grid\_meta, step)
$$

在 §8 的概率场上叠加所有活跃负向核。

### 9.3 Layer 2：访问密度惩罚

构建访问密度场 $V(x,y)$，记录每个位置被多少次访问过：

$$
V(x,y) = \sum_{p \in \text{visited}} \exp\left(-\frac{(x - p_x)^2 + (y - p_y)^2}{2\sigma_v^2}\right)
$$

其中 $\sigma_v = 2.0$ m（扩散半径）。

**关键**：不对 $V$ 做归一化——3 次访问的区域 $V \approx 3$，忠实反映访问频率。

### 9.4 Layer 3：Flatness 判定与模式切换

在可导航区域（$M_{free} = 1$）上检测概率场的平坦性：

$$
\text{is\_flat} = \left(\frac{P_{max}}{P_{mean}} < r_{flat}\right) \quad \text{or} \quad (P_{max} < 10^{-10})
$$

$r_{flat} = 3.0$（若最大值不到均值 3 倍，认为缺乏明确峰值）。

**如果 is_flat = True → Frontier 模式**：

$$
score(x,y) = -V(x,y), \quad score[M_{free} = 0] = -\infty
$$

选择**访问密度最低**的可导航区域（即"去探索最少去过的地方"）。

**如果 is_flat = False → GMM 引导模式**：

$$
\beta = \frac{P_{max}}{3.0}
$$

$$
score(x,y) = P_{corrected}(x,y) - \beta \cdot V(x,y)
$$

**物理含义**：$\beta$ 的设计使得一个位置被访问 3 次后，其概率场值被完全抵消（$\beta \times 3 = P_{max}$），从而强制 agent 探索新区域。

### 9.5 目标点选取

$$
(r^*, c^*) = \arg\max_{x,y} score(x,y)
$$

$$
\text{nav\_target} = \text{snap\_to\_free}\left(\text{grid\_to\_world}(r^*, c^*)\right)
$$

- **navmesh 模式**：使用 Habitat 的 `pathfinder.snap_point()` 将目标点对齐到最近的可导航点
- **GT-free 模式**：使用 `_snap_to_free()` BFS 在占据栅格上找最近 free cell

### 9.6 路径规划

规划：使用voronoi_navigator 的 `get_path_to_target()` 规划路径点列表 + 实时路径避障

目的：
1. 深度探索模式遍历环境，voronoi_navigator 的全局路径规划能力能有效引导 agent 穿过复杂环境，避免局部最优。
2. 主要：task模式利用voronoi_navigator 的路径规划加快规划，并且voronoi点多位于正中间，便于机器人观察环境进行局部更新（若使用各种导航算法容易1. 算力需求高 2. 规划出的路径位于边缘导致观察过多无效信息）

以前：

使用 A* 算法在占据栅格上规划从 agent 当前位置到目标点的路径，按 step_size（0.5m）采样路径点。

栅格 A* 使用膨胀后的可导航掩码（`get_navigable_map(layer="merged")`），8邻域搜索，支持对角线移动。

### 9.7 行走安全机制（v0.7 新增，v0.8 增强） | 初步思路，待完善逻辑

#### 连续步进与碰撞偏转恢复（v0.8）

任务导航模式使用连续步进 `move_to_waypoint()`，通过 `agent.act("move_forward")` + `agent.act("turn_left/right")` 序列模拟真实运动。当 `move_forward` 被 habitat mesh 碰撞检测阻挡时（`moved < 0.01m`），执行碰撞偏转恢复：

$$
\theta_{nudge} \in \{+15°, -15°, +30°, -30°, +45°, -45°\}
$$

依次尝试偏转后再前进，任一方向移动 $> 0.05m$ 即视为脱困成功。全部失败才放弃当前 waypoint。

模块：`nav_core/habitat_agent.py` 中 `move_to_waypoint()`

#### 前方碰撞检测

在执行每个路径点的 `move_to_waypoint()` 前，调用 `check_collision_ahead(pos, heading, check_distance)`，基于 `current_frame + short_term` 层检查前方是否有障碍物。如有碰撞，**跳过该路径点**继续下一个。

模块：`occupancy_grid.py` 中 `check_collision_ahead()`

#### 卡点检测与恢复

**StuckDetector**（滑动窗口检测 + 多级恢复）：

$$
\text{is\_stuck} = \left(\max_{i,j \in W} \|pos_i - pos_j\|_2 < d_{min}\right), \quad |W| = 5, \; d_{min} = 0.5 \text{ m}
$$

当检测到卡点时，调用 `recover_from_stuck()` 恢复，尝试随机方向移动脱困。

模块：`nav_core/voronoi_navigator.py` 中 `StuckDetector`, `recover_from_stuck()`

### 9.8 多视点调查模式（v0.7 新增，核心创新 C5）

当 agent 到达 GMM 引导的目标点后，并不立即宣布搜索失败或成功，而是在目标区域进行**主动调查**（active investigation）：

1. **概率峰值定位**：在概率场 `prob_field_base` 上找到全局峰值 $(r_{peak}, c_{peak})$
2. **视点生成**：在峰值周围 $d_{standoff}$（默认 1.5m）距离的圆上均匀采样 $n$ 个候选方向（默认 $n = 3$）
3. **可达性修正**：对每个候选位置，用 BFS 搜索最近的 FREE cell 作为实际观测站位
4. **观测执行**：在每个视点做完整 360° 环视观测

$$
\theta_k = \frac{2\pi k}{n}, \quad k = 0, 1, \ldots, n-1
$$

$$
p_k = \mu_{peak} + d_{standoff} \cdot [\cos\theta_k, \sin\theta_k]
$$

$$
p_k^{free} = \text{BFS\_nearest\_free}(p_k, grid)
$$

**物理含义**：从多个角度观察目标区域，避免因单一观测方向的遮挡而产生假阴性。例如，目标物体（微波炉）可能被冰箱正面遮挡，但从侧面可以看见。

模块：`nav_core/nav_strategy.py` 中 `generate_investigation_viewpoints()`, `_bfs_nearest_free()`

### 9.9 HOV-SG 房间分割与 Voronoi 拓扑图（v0.6 新增）

#### 房间分割

基于占据栅格的 HOV-SG 风格分割流程：

1. **墙壁骨架提取**：$grid \neq FREE \rightarrow$ 二值图 → GaussianBlur → 阈值化 → 形态学闭运算
2. **距离变换**：$D(x,y) = \text{cv2.distanceTransform}(free\_space, \text{DIST\_L2})$
3. **Otsu 自动阈值**：$\hat{D} = \text{Otsu}(GaussianBlur(D))$ → 种子区域（距墙壁远的中心）
4. **分水岭分割**：$\text{cv2.watershed}(markers)$ → 完整房间边界

模块：`semantic_map_Create/room_segmentation.py`

#### Voronoi 拓扑导航图

1. **自由空间边界提取**：`binary_erosion(free_map)` → 边界点
2. **Voronoi 图**：`scipy.spatial.Voronoi(boundary_points)` → 原始图
3. **过滤**：只保留两端+中点都在 free 内的 Voronoi 边
4. **稀疏化**：移除 degree-2 节点 + 合并过近节点（$< min\_node\_dist$）
5. **输出**：`networkx.Graph`，节点 `{pos_world, pos_grid, room_id}`，边 `{dist}`

$$
G_{voronoi} = \text{sparsify}(\text{filter}(\text{Voronoi}(\partial \mathcal{F})))
$$

其中 $\partial \mathcal{F}$ 为自由空间边界点集。

模块：`semantic_map_Create/voronoi_graph.py`

用于任务模式的跨房间高效路径规划（利用 Voronoi 图的拓扑结构识别走廊/门道等瓶颈点）。

## 11. 已知问题与局限性

### 11.1 物体膨胀仍未完全解决

**现象**：microwave 测试中物体从 262 增至 560（+298）。

**根本原因分析**：

| 原因 | 贡献度 | 说明 |
|------|--------|------|
| **真新物体** | ~40% | GroundingDINO 检测出预建地图未包含的类别（bed, wardrobe, shelf cabinet 等） |
| **跨步重复** | ~40% | 同一物体在不同步被检测，pos_3d 偏移导致超过匹配阈值 |
| **标签近义泛滥** | ~20% | "shelf cabinet" vs "shelf bookshelf cabinet" vs "shelf" CLIP cosine 可能低于 0.65 |

**可能的改进**：
- 降低 $\tau_{clip}$ 从 0.65 到 0.55
- 降低 $\tau_{match}$ 从 0.55 到 0.45
- 增大 $d_{norm}$ 从 3.0 到 5.0（对距离更宽容）
- 引入 3D IoU 替代 2D IoU（解决三维堆叠误判）

### 11.2 仅 2D IoU 的三维堆叠误判

**问题**：杯子在桌子上方，2D 俯视图 bounding box 高度重叠。杯子被拿走后，桌子的 2D box 仍在原位，可能导致误匹配。

**解决方案**（规划中）：引入 `z_range` 高度区间检验，将 2D IoU 升级为 3D 边界框重叠检测。

### 11.3 map_Update 按房间调用 object_update

**问题**：`map_Update.py:248` 中 `object_update()` 是按房间调用的——对每个 `room_now` 匹配同 `room_id` 的 `room_hist`。即使 CLIP 模式声称搜索"全部历史物体"，传入的 `objs_history` 实际只有**同房间**的物体。

**影响**：物体被分配到 R3 后，只能与 R3 的 88 个预建物体匹配，不能与 R1 的物体匹配。如果 room_id 分配有误（pos_3d 最近邻不够精确），可能产生跨房间重复。

**改进方向**：跨全楼层 CLIP 匹配（在 map_Update 层面搜索所有房间），或提高 room_id 分配精度（使用房间多边形 point-in-polygon 代替最近邻）。

### 11.4 GT 语义传感器不可用

HM3D v0.2 格式场景缺少 `.basis.scn` 和 `info_semantic.json` 文件，habitat_sim 0.3.3 的 GT 语义传感器返回全零图像。即使添加 `use_semantic_textures=True` 也无法修复。

**影响**：`--use-gt-semantic` 模式完全不可用，但这也推动了系统完全转向视觉检测模式（GroundingDINO + MobileSAM），使系统不再依赖任何 GT 数据。

### 11.5 `source_mode` 字段未添加

Object 模型中尚未添加 `source_mode` 字段，无法区分深度探索和任务模式的产出物体。当前统一使用 `pos_ema_alpha = 0.3`。

### 11.6 时间衰减使用虚拟时钟

当前使用虚拟时钟（每步推进 1 小时），不是真实时间差。在单次导航任务中（总时间跨度约 18 小时），时间衰减的影响微乎其微。真实场景下需使用真实时间戳。
