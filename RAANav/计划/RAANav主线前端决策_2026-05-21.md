# RAANav 主线前端决策记录（2026-05-21）

## 决策

主线抛弃 GroundingDINO + MobileSAM 仿真前端，也不把 DAM/VLM 描述模型放进核心闭环。

新的主线是：

```text
RGB-D-pose source
  -> FastSAM segmentation
  -> BotSort tracking
  -> representative assignment per track
  -> CLIP object-node embedding/top-k label
  -> RAANav object-node memory / map update / GMM
```

## 理由

论文核心是轻量长期语义建图和变化环境中的重复建图，不是生成自然语言描述。系统需要稳定 object node、位置、时间、共现、CLIP embedding 和观测统计。DAM/VLM 可作为未来 fallback，但不是主线依赖。

## 2026-05-21 补充决策

- 空检测/空轨迹是正常情况，不是必然代码 bug。机器人可能看向白墙、地面、强反光、运动模糊、遮挡区域，或者分割结果被质量过滤器全部丢弃。代码需要把它当成一类合法输入处理。
- 入口层已增加空轨迹防护：当没有检测时不调用容易崩溃的 tracker 更新路径；当 tracker 返回 `None`、空数组或一维数组时统一规范成 `(0, 8)` 或 `(1, N)` 的二维数组。
- `smoke test` 只表示最小链路能启动和写输出，不表示算法效果通过。
- ReID 是 re-identification，用于跨遮挡、跨短暂消失恢复同一物体身份。当前 ReID 依赖 TensorRT engine，而 `daaam_p0` 没有 TensorRT，所以中短期不把 ReID 作为验收阻塞项。
- 因为没有 ReID 时 track 更容易碎裂，主线不再只依赖单个 track 自身稳定，而是把所有高质量 3D observations 进行空间聚类，生成 `object_nodes`。RAANav adapter 优先消费 `object_nodes`，没有时才回退到 `tracks`。
- 结构性物体不应被一刀切过滤。栏杆、门框、柜体边缘等如果语义和几何稳定，可以作为长期地图锚点。当前过滤器只优先排除巨大边缘平面、过大墙/地面 mask 和明显劣质 mask。
- 地面/floor mask 有价值，但不应进入 object-node 语义检索主体。它更适合作为可通行区域、相机高度/尺度 sanity check、地平面约束和后续导航代价地图输入。当前阶段先不引入 dense world/per-point CLIP 地图，避免显著增加计算和内存。
- CLIP 权重本地缓存后，HuggingFace/open_clip 仍可能做元数据 HEAD 检查。默认设置 `HF_HUB_OFFLINE=1`，保证重复实验不被网络卡住；只有缺模型时临时打开代理下载。
- RTX 5060 Ti 需要支持 `sm_120` 的 PyTorch/CUDA 组合。不要在现有 `agentrag`、`sem-map`、`daaam_p0` 环境中直接盲目升级 torch；应新建验证环境，跑通 CUDA、FastSAM、open_clip、BotSort 后再替换主线命令。
