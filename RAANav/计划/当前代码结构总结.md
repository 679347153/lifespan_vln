#### 占据栅格与导航规划详解

系统中存在**两套栅格**，分别用于不同目的：

##### 1. 离线静态栅格（磁盘预建）

```
RAG_Graph/scene_build/occupancy_grid/
├── occupancy_grid.npy     ← 2D 数组 (H×W), 值: 0=unknown, 1=free, 2=occupied
└── occupancy_meta.npz     ← {origin: [x, z], resolution: 0.05, shape: [H, W]}
```

- **生成时机**: `map_Create.py` 离线一次性生成（阶段 A）
- **数据源**: Habitat navmesh 采样 → 点是否 `is_navigable()` → 标记 free/occupied
- **用途**: 
  - `build_probability_field()` 中作为 GMM 高斯核的画布（`free_mask` 约束概率场不穿墙）
  - `visualize_and_extract_topk()` 中绘制热力图底图
- **局限**: 尺寸固定、不随导航更新；robot探索新区域时不会扩展

##### 2. 运行时活动栅格（内存动态）

```python
# 模式 A: navmesh 基线 (默认)
occ_grid = OccupancyGrid.from_navmesh_fast(sim, resolution=0.05, agent_radius=0.18)
occ_grid.init_persistent_from_navmesh()  # persistent 层 = navmesh 可通行性

# 以 agent 为中心创建空白栅格, 脚下标一小圆 free, 纯深度增量构建
```

- **生成时机**: `run_sim_nav_loop()` 启动时从 navmesh 新建
- **数据源**: navmesh 采样 + 每步深度传感器实时更新
- **特点**: 可动态扩展（`_ensure_capacity()`）、三层架构、支持碰撞检测
- **用途**: A* 路径规划、可视化仪表盘、frontier 决策

##### 两套栅格的关系与同步

```
                    离线预建栅格 (磁盘)              运行时活动栅格 (内存)
                    ──────────────────              ─────────────────────
生成时机            map_Create.py 一次性            sim_nav_loop 每次运行时
大小                固定 (如 333×340)               动态扩展 (随探索增长)
原点                采样时确定, 固定不变             navmesh_fast() 时确定, 可能不同
数据更新            不更新                          每帧深度传感器更新
层级                单层 (0/1/2)                    三层 (persistent + short_term + current_frame)
用于A*              ✗                               ✓ (仅用 persistent 层)
用于GMM概率场       ✓ (之前) → ✗ (已修复)           ✓ (现在直接使用活动栅格)
用于可视化          ✗                               ✓
```

> **重要修复**: 之前 `build_probability_field()` 从磁盘加载离线栅格，但活动栅格可能有不同的尺寸和原点，
> 导致 GMM 高斯核被画在错误的位置。现已修改为直接传入 `occ_grid.grid` + live meta。

##### 三层栅格架构

```
Layer 1: persistent（持久层）
  ├─ 初始化: navmesh 标记 → free=墙外可通行, occupied=墙壁/结构
  ├─ 更新: 高 stability 物体可加入 (update_persistent_from_objects)
  ├─ 用途: A* 全局路径规划 ← 只用这一层
  └─ 颜色: 深蓝 [100, 50, 20]

Layer 2: short_term（短期层）
  ├─ 数据源: 最近 K=20 帧深度传感器的障碍物投影取并集
  ├─ 语义: 家具表面、近处墙壁、动态障碍物等
  ├─ 更新: 每帧 append → pop oldest → np.maximum 累积
  ├─ 用途: 局部避障参考（当前未接入 A*）
  └─ 颜色: 橙色 [0, 140, 255]

Layer 3: current_frame（当前帧层）
  ├─ 数据源: 仅当前这一帧深度传感器的障碍物投影
  ├─ 生命周期: 下一帧覆盖
  ├─ 用途: 即时反应
  └─ 颜色: 红色 [0, 0, 255]

合并后主栅格 (self.grid):
  ├─ 深度传感器仅将 UNKNOWN → OCCUPIED，不覆盖 navmesh 确定的 FREE
  ├─ v0.2 修复: 防止深度障碍覆盖 navmesh 走廊
  ├─ v0.7 修复: _navmesh_free 掩码保护 navmesh 确认 FREE 不被深度 obstacle 覆盖
  └─ A* 仅看 self.grid 中 OCCUPIED，而非三层合并
```

##### 导航决策与概率场

```
┌─ 输入: floors_history 中的物体 ──────────────────────────┐
│                                                           │
│  1. CLIP 搜索: _clip_search_in_memory(target, 0.85)      │
│     → 命中物体列表 [(obj_id, cosine_score)]               │
│                                                           │
│  2. GMM 评分: _score_from_memory(target, clip_hits)       │
│     → {obj_id: score} + {obj_id: [world_x, world_z]}     │
│                                                           │
│  3. 概率场构建: build_probability_field()                  │
│     ├─ 输入: gmm_scores, gmm_positions, 活动栅格          │
│     ├─ 每个物体 → 2D 高斯核 (μ=pos, σ=1.5m, amp=score×3) │
│     ├─ 叠加到 prob 数组 (v0.7: 不再 × free_mask)          │
│     └─ 输出: prob_field_base (未归一化, 不受障碍物约束)    │
│                                                           │
│  4. 导航决策: frontier_exploration_step()                  │
│     ├─ 负向高斯修正: neg_field.apply(prob_field_base)      │
│     ├─ 访问密度惩罚: visit_density (σ=2m, 不归一化)       │
│     ├─ 平坦判定: prob_max/prob_mean < 3.0 ?               │
│     │   ├─ Yes → frontier 模式 (去访问密度最低区域)        │
│     │   └─ No  → gmm 模式 (去概率最高点)                  │
│     └─ snap_point → 最近可导航点                          │
└───────────────────────────────────────────────────────────┘
```

#### CLIP 零样本分类器设计（`clip_labeler.py`）

核心设计参考 DAAAM 的 `CLIPHandler`（`utils/embedding.py`）：
- **模型**: `open_clip` ViT-B-16（openai 预训练权重）
- **标签库**: 65 类室内标签 → 别名去重 → 53 个 canonical 标签
- **文本嵌入**: 预计算 "a photo of a {label}" 提示词嵌入并缓存
- **分类**: 图像 crop → CLIP 图像嵌入 → softmax(cos_sim / τ), τ=0.5
- **输出**: `{label, confidence, clip_embedding}` per mask

### v0.8.2 核心改动

**1. 跨楼层导航修复 — 4处楼层过滤 (FLOOR_Y_THRESHOLD=1.5m)**
- **根因**: 整个 CLIP搜索→GMM评分→概率场→导航目标→snap_point 管线无 Y/楼层意识，所有楼层投影到同一 XZ 平面。机器人在2楼(y=2.8)却导航到1楼目标(y≈0.2)，走不过楼梯被卡死。
- `_clip_search_in_memory()` (sim_nav_loop.py): 跳过 `|obj.pos_3d[1] - agent_y| > 1.5m` 的异层物体
- `_score_from_memory()` (sim_nav_loop.py): 同上，过滤 GMM 评分候选物体
- `frontier_exploration_step()` (nav_strategy.py): snap_point 后验证 `|nav_point[1] - agent_y| < 1.5`
- `get_random_navigable_point()` (habitat_agent.py): navmesh 随机采样时循环最多30次过滤同楼层

**2. 目标检测硬化 (sim_nav_loop.py)**
- **根因**: `target_seen` 仅判断 `label == target` 即报告 TARGET FOUND，GroundingDINO 对模糊墙壁纹理的假阳性导致虚假成功
- 新逻辑: 要求 `pos_3d` 距离 < 5m **或** bbox 面积 > 2% 图像面积，简单标签匹配不再足够
