# 对象节点前端问题解答（2026-05-21）

本文记录当前关于 DAAAM-style 前端、tracking、CLIP、本地模型、地面 mask、ReID 和 5060 Ti 环境的决策。写给后续 AI 和自己复盘用。

## 1. 为什么 BotSort 会返回空轨迹

空轨迹是正常情况，不等于代码 bug。常见原因：

- 当前帧没有可靠分割结果，例如白墙、地面、玻璃、强反光、运动模糊、遮挡。
- 分割服务有输出，但质量过滤器把大平面、边缘大 mask 或劣质 mask 全部丢掉。
- tracker 初始化早期、遮挡后短暂丢失，或者检测置信度不足。

代码 bug 在于：上游服务把空结果表达成一维空数组时，下游仍按二维数组索引。正确处理方式不是伪造一个目标，而是把空结果规范成 `(0, 8)` 的二维空轨迹，然后当前帧输出 `n_tracks=0`，主线继续跑。

当前入口层处理：

- `len(dets)==0` 时跳过 tracker 更新路径，直接产生空 tracks。
- tracker 返回 `None`、空数组、一维数组时统一规范化。

## 2. smoke test 和 ReID

`smoke test` 是最小冒烟测试，只验证链路能否启动、交换数据、写出文件。它回答的是“会不会一运行就炸”，不是“效果好不好”。

ReID 是 re-identification。它解决的是：同一个物体被遮挡、离开视野、重新出现以后，tracker 能否把它认回原来的身份。没有 ReID 时，同一把椅子、同一个柜子、同一段栏杆很容易被分成多个短 track。

## 3. 为什么本地有 CLIP 还会访问 HuggingFace

很多模型库会把“权重文件缓存”和“远程元数据检查”分开处理。即使本地已有权重，它仍可能向 HuggingFace 发 `HEAD` 请求确认 revision、etag 或文件新鲜度。网络差时，这类检查会拖慢几十秒甚至超时。

当前策略：

- 默认 `HF_HUB_OFFLINE=1`，重复实验只用本地缓存。
- 缺模型时临时打开代理下载，下载成功后恢复离线模式。
- 模型加载逻辑保留在 `AgenticRAG/scripts/daaam/clip_labeler.py`，前端只调用统一 labeler。

## 4. RTX 5060 Ti / sm_120 / PyTorch

5060 Ti 需要支持 `sm_120` 的 PyTorch/CUDA 组合。当前 cu124 PyTorch 能看到卡但提示不支持，说明“能发现 GPU”和“能正确跑 kernel”不是一回事。

处理原则：

- 不在 `agentrag`、`sem-map`、`daaam_p0` 里直接盲目升级 torch。
- 新建一个独立 CUDA 验证环境，例如 `raanav_cuda`。
- 先验证 `torch.cuda.is_available()`、简单 tensor kernel、FastSAM、open_clip、BotSort。
- 验证通过后再把主线命令切到新环境，避免破坏 Habitat 或 DAAAM 已有依赖。

## 5. 地面 mask 是否有必要

地面/floor mask 有必要，但不应该成为 object-node 语义检索主体。

参考 HOV-SG/DOVSG 这类开放词汇 3D scene graph 工作，floor/room/object 层级可以帮助组织空间；地面或楼层分割常用于层级图、可通行空间、区域约束和导航，不是为了把“floor”当成普通目标物反复检索。

本项目建议：

- 保留地面作为导航和几何辅助信号。
- 不把大地面 mask 放进 object-node GMM 主体。
- 后续可用地面做相机高度 sanity check、可通行区域、代价地图、位姿漂移检测。
- 当前不做 dense per-point CLIP world map，避免算力和显存开销突增。

## 6. track 怎么生成，为什么会碎裂，空间聚类怎么做

流程：

```text
每帧 RGB
  -> FastSAM 产生 masks
  -> 每个 mask 转成 bbox/score
  -> BotSort 根据 bbox 运动一致性、IoU、外观 ReID 尝试把当前帧 detections 接到已有轨迹
  -> 得到 track_id
```

同一物体会被多个短 track 看到，是因为真实移动中会有视角变化、遮挡、光照变化、mask 形状变化、检测漏帧、近距离裁剪和 ReID 缺失。没有 ReID 时，tracker 主要依赖几何/运动连续性，一旦物体消失几帧或外观变化大，就更容易断成新 ID。

空间聚类做法：

- 每个 mask 用深度和相机位姿反投影成一个 3D observation。
- 对所有高质量 observations 按世界坐标 x/z 距离聚类。
- 半径内的观测合并成一个 object node。
- object node 记录来源 track IDs、观测次数、代表 crops、平均位置、位置方差、CLIP embedding/top-k label。

这不是用完整点云建 dense map，而是用 RGB-D 反投影得到轻量 3D 节点。它能容忍 tracking 碎裂，也符合长期轻量地图目标。

## 7. ReID / TensorRT

当前 DAAAM ReID 依赖 TensorRT `.engine`，而环境里没有 TensorRT。这个可以修，但不适合和主线语义验收混在一起修，因为 TensorRT、CUDA、PyTorch、显卡架构之间容易互相牵连。

短期策略：

- 下一轮验收允许 `--without-reid`。
- 用 spatial object-node clustering 弥补短 track。
- 单独开一个环境任务修 TensorRT ReID，修好后再 A/B 对比：ReID on vs off 的 track fragmentation、object node 数量、GMM 稳定性。

## 8. 代理

裸连 HuggingFace 当前会超时。机器上能找到 `/usr/bin/clash`，实际监听进程是 `mihomo`，命令行代理端口已验证为 `127.0.0.1:7890`。shell 环境没有自动继承桌面 UI 代理变量，命令行下载模型时需要显式设置：

```bash
export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
```

如果端口后续被改，用 Clash UI 或命令行配置里的 mixed-port/http-port 为准。

## 9. 对结构性物体的最终态度

不要粗暴过滤结构性物体。栏杆、门框、固定柜体、墙上固定装置如果识别稳定，可以提供长期地图锚点，并帮助判断机器人是否漂移。

当前主线只过滤：

- 巨大的地面/墙面平面；
- 贴边的大面积 mask；
- 极端劣质的形状 mask。

后续 object node 可以增加 `node_type`：

- `object`: 普通可查询物体；
- `structural_anchor`: 栏杆、门框、固定结构；
- `support_surface`: 桌面、台面；
- `floor_or_free_space`: 导航辅助，不进物体语义检索。
