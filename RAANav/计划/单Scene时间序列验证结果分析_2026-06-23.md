## 4. 可能的问题分支

如果诊断结果为 `retrieval_no_candidates`：

- 检查 `observation_traces.jsonl` 中是否有 detection。
- 检查 detection 是否带 `clip_embedding_dim`。
- 检查目标 label 是否出现在 prompt label 列表或 memory 中。
- 尝试降低或显式设置 `--clip-min-score 0.15` 到 `0.2`，提高远程 CLIP text-image 召回。

如果诊断结果为 `candidates_far_from_goal`：

- 检查 `candidate_traces.jsonl` 中 top candidates 的 label、`sim_backend`、`S_final` 和目标距离。
- 增强 alias 与 target object 的规范化，避免目标名和检测名错配。
- 检查 `scene_memory_final.json` 中同类物体是否持续停留在旧 layout 位置。
- 分析 negative feedback 是否有效降低旧位置权重。

如果诊断结果为 `candidate_near_but_navigation_or_success_radius_failed`：

- 将 `--max-steps-per-subtask` 提高到 `80`。
- 将 `--max-rounds` 提高到 `5`。
- 将 `--micro-steps-per-round` 提高到 `8`。
- 检查最终观测是否因为视角、遮挡或检测阈值未确认目标。

如果诊断结果为 `perception_empty` 或 `memory_not_updated`：

- 检查远程服务健康状态：

```bash
curl http://127.0.0.1:50220/health
```

- 检查单图检测和 CLIP：

```bash

  --image objects_images/Camera_01.webp \
```

这组结果说明，当前系统已经不是早期的“远程感知不可用”或“候选为空”问题：

- 感知链路强：远程视觉调用 `1180` 次，失败 `0` 次，检测 `4696` 个目标。
- CLIP 链路正常：所有检测均返回 `768` 维 embedding，没有 512/768 混用。
- 候选召回正常：`137/137` 轮都有候选，平均每轮 `8.53` 个候选，没有 fallback 到随机点。
- 记忆链路正常：`4313` 个 memory events，其中包含 `1097` 次 `migrated` 和 `124` 次 `negative_feedback`。

因此，本轮主要瓶颈不是“没有感知、没有候选、没有记忆”，而是：

1. **感知确认与 benchmark 真值成功条件存在错位**  
   `perception_found=34`，但真正落入 benchmark 成功半径的 `found=2`。这表示系统多次认为已经看到了目标，但最终位姿离真实目标仍较远。可能原因包括 label 过宽匹配、开放词汇检测误检、目标别名混淆、同类物体替代目标、或最终成功条件只认 dataset target position。

2. **候选接近目标但未转化为成功**  
   `ghr5=20` 表示 74 个 subtask 中有 20 个任务的 top-5 候选曾经靠近真实目标；`mra=9` 表示 top-1 候选也有 9 次靠近目标。但最终 `found=2`，说明候选排序、候选执行、最终观测确认或 success radius 对齐仍有问题。

3. **导航执行可能偏离候选最优点**  
   平均候选最小距离为 `1.97m`，但最终距离为 `4.38m`。即使候选集中出现过较好位置，最终停留点仍可能因为 micro-step 预算、路径截断、选错 top-1、或中途误判目标已发现而未充分靠近。

4. **长期记忆已经出现后期收益信号**  
   在 `seen_layout_count_before=9` 时：

   ```text
   found_rate = 0.2857
   mra = 0.5714
   ghr3 = 0.7143
   ghr5 = 0.7143
   avg_min_dist = 0.2940
   ```

   相比 `seen_layout_count_before=0` 的 `found_rate=0.0`、`avg_min_dist=3.05`，后期 layout 的候选质量明显提升。这是正向信号，说明长期记忆不是完全无效；问题在于整体曲线仍不稳定，且候选质量尚未稳定转化为 episode-level success。

## 7. 下一阶段优先修正方向

### 7.1 修正目标确认逻辑

当前 `_target_detected()` 只基于 label/token overlap 判断目标是否被看见，容易把同类物体、重复词 label 或宽泛检测当成 benchmark 目标。建议下一步增加空间一致性约束：

- 只有检测 label 匹配且检测 2D/3D 位置接近当前 subtask 的 target position 时，才把 `perception_found=True`。
- 将“语义看见目标”和“benchmark 位置成功”分开记录，例如 `semantic_detected` 与 `spatial_success`。
- 对 image-goal 和 language-goal 任务，避免只用 object name 判断目标，应结合 CLIP 相似度和空间位置。

### 7.2 加强候选执行与最终成功转化

因为 `ghr5` 和 `mra` 已经有非零信号，下一步应提高“好候选 -> 成功”的转化率：

- 当 top-5 中存在接近目标的候选但 top-1 失败时，记录候选排序错误。
- 到达 top-1 后若未发现目标，不要立即结束该 subtask，应尝试 top-2/top-3。
- 增加每轮候选执行后的局部环视确认次数。
- 增加 `--max-steps-per-subtask` 和 `--max-rounds`，但优先配合候选重试逻辑，而不是盲目扩大预算。

### 7.3 清洗和规范化检测 label

诊断中出现大量重复或拼接标签，例如：

```text
mirror mirror picture
brass pot brass pot
metal metal metal metal metal
shelf cabinet shelf cabinet
```

这会影响 memory 合并、候选排序和 negative feedback。建议增加 label canonicalization：

- 去除连续重复 token。
- 将 `mirror picture`、`picture mirror picture` 等合并为稳定 alias。
- 为数据集目标名建立 alias 表，例如 `Antique Ceramic Vase 01 4K -> antique ceramic vase / vase`。
- 在 memory 中同时保存 `raw_label` 和 `canonical_label`，检索和融合评分使用 canonical label。

### 7.4 报告长期曲线而非单一 SR

虽然 episode-level `success_rate=0.0`，但 `seen_layout_count_before=9` 的 `GHR@5=0.7143` 和 `avg_min_dist=0.2940` 表明长期记忆已经有晚期改善信号。后续报告中应同时展示：

- episode-level SR/SPL
- subtask-level found rate
- GHR@3/GHR@5
- MRA
- avg candidate min distance
- 按 `seen_layout_count_before` 的趋势曲线

这能更准确地区分“系统完全无效”和“候选已接近但成功判定/执行尚未对齐”。

## 9. 对三条调参建议的可行性判断

### 9.1 降低 CLIP 阈值

该建议可行，但不应预期它必然显著提升 `found_rate`。

理由：

- 工程上已经支持 `--clip-min-score`，本轮已建议使用 `0.15`。
- 降低阈值会提高远程 CLIP text-image 检索召回，可能让更多检测到的目标进入候选集合。
- 但上一次诊断中 `rounds_with_candidates=137/137`，说明候选召回本身不是最主要瓶颈；真正瓶颈是候选和 benchmark 真值成功条件未完全对齐。
- 因此降低阈值应重点观察 `GHR@3/GHR@5`、`avg_candidate_min_dist` 和 `found_rate`，而不是只看候选数量。

推荐值：

```bash
--clip-min-score 0.15
```

### 9.2 目标名称映射

该建议非常合理，已完成工程修改。

新增能力：

- `--target-name-map`
- `--normalize-target-names`
- 内置 alias 规则
- 配置文件：`RAANav/AgenticRAG/config/target_name_map_longterm_v1.json`

典型映射：

```text
Chess Set 4K / chess_set -> chess, chess_set
Camera_01 -> camera, camera_01
Alarm Clock 01 4K / alarm_clock_01 -> alarm_clock, clock
Tea Set 01 4K / tea_set_01 -> tea_set, tea
```

影响范围：

- 检测目标确认。
- 远程 CLIP 文本查询。
- Agent/RAG 融合评分中的 label similarity。
- image-goal 缺图时的 label fallback。
- 输出诊断中的 `alias_labels`。

### 9.3 增加步数

该建议可行，且对当前结果有必要。

理由：

- 上次 `avg_steps=40.5` 已接近 `--max-steps-per-subtask 40`，说明搜索经常触及预算边界。
- `avg_candidate_min_dist=1.97m` 但 `avg_final_dist=4.38m`，说明好候选未稳定转化为最终位置成功。
- 增加 `--max-steps-per-subtask`、`--max-rounds`、`--micro-steps-per-round` 可以提高候选执行和局部重试机会。

推荐下一轮：

```bash
--max-steps-per-subtask 80
--max-rounds 5
--micro-steps-per-round 8
```

但需要注意：如果不修正目标名称映射和空间确认，单纯增加步数可能只是更久地追逐错误候选。
