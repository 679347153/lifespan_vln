## 一、自定义评价指标体系

你的核心论点是：**我们评价的是"大脑"（记忆+决策），不是"双腿"（路径规划）**。因此指标体系应围绕三个维度设计：

### 维度 A：记忆质量（Memory Quality）

| 指标 | 名称 | 数学定义 | 含义 |
|------|------|---------|------|
| **MRA** | Memory Recall Accuracy | 在时刻 $T_k$ 查询物体 $o$，系统 GMM 概率场的 Top-1 峰值与 $o$ 当前真实位置 (GT) 的欧氏距离：$MRA(o, T_k) = \mathbb{1}[\|p_{top1} - p_{gt}\|_2 < r_{hit}]$，$r_{hit}$ 取 2m | 不让机器人移动，纯评估"地图记得准不准"。可大批量跑。 |
| **GHR@K** | GMM Hit Rate @ K | GMM 概率场 Top-K 峰值中，是否有至少一个落在 GT 位置 $r_{hit}$ 范围内：$GHR@K = \frac{1}{\|Q\|}\sum_{q \in Q}\mathbb{1}[\exists k \leq K: \|p_k - p_{gt}\|_2 < r_{hit}]$ | 放宽到 Top-3/Top-5，体现系统"候选列表"的覆盖质量 |

### 维度 B：动态适应能力（Dynamic Adaptation）

| 指标 | 名称 | 数学定义 | 含义 |
|------|------|---------|------|
| **D-SR** | Dynamic Object Success Rate | 仅针对跨 epoch 发生位置变化的物体统计成功率：$D\text{-}SR = \frac{\text{moved objects found}}{\text{total moved objects}}$ | 这是**最核心**的指标。静态物体大家都能找到，动态物体才拉开差距 |
| **AS** | Adaptation Speed | 物体在 $T_k$ 被移动后，系统需要多少轮额外探索才能让 GMM Top-1 指向新位置：$AS(o) = \min\{n : MRA(o, T_{k+n})=1\}$ | 值越小说明适应越快。负向高斯场+时间衰减应显著降低此值 |
| **SSS** | Semantic Search Steps | 机器人找到目标前，前往的 GMM 高概率候选区域数量 | 替代 SPL。只计"去了几个候选点"，不计物理路径长度。SSS=1 意味着一次命中 |

### 维度 C：长期学习（Long-term Learning）

| 指标 | 名称 | 数学定义 | 含义 |
|------|------|---------|------|
| **MRR** | Memory Retention Rate | 物体 $o$ 在最后一次被观测后，经过 $\Delta t$ 个 epoch 未被重新观测，系统对其位置预测仍正确的比例 | 验证时间衰减机制——稳定物体（冰箱）应长时间保持记忆，不稳定物体（杯子）应加速遗忘 |

### 保留的传统指标（作为参考基线）

| 指标 | 说明 |
|------|------|
| **SR (Success Rate)** | 整体成功率，但我们会拆分为 Static-SR 和 Dynamic-SR |
| **FR-Acc** | LLM Agent 预测的首选房间是否正确——验证 C5（动态权重融合）中 Agent 通道的贡献 |

### 论文中如何呈现

论文表格建议分两组：

## 二、长期动态数据集构建方案

### 2.1 核心设计理念

数据集要模拟**同一场景在时间维度上的演变**。不是多场景横向对比，而是**单场景纵向对比**（类比一个人住在同一个家一个月）。

### 2.2 物体变化分类（五类）

| 类别 | 缩写 | 定义 | 例子 | stability 范围 |
|------|------|------|------|---------------|
| **静态物体** | SO (Static Object) | 全部 epoch 位置不变 | 冰箱、浴缸、沙发 | 0.85–1.0 |
| **低频迁移** | LRO (Low-freq Relocated) | 仅在某 1-2 个 epoch 被移动一次，之后稳定 | 书架、台灯、植物 | 0.6–0.85 |
| **高频迁移** | HRO (High-freq Relocated) | 几乎每个 epoch 位置都变，但在固定几个"常驻点"间切换 | 椅子、靠垫、遥控器 | 0.3–0.6 |
| **消失物体** | DO (Disappeared Object) | 在某 epoch 后被移出场景 | 纸箱、临时物品 | N/A |
| **新增物体** | NO (New Object) | 在某 epoch 才首次出现 | 新买的电器、新摆件 | N/A |

### 2.3 时间线结构

建议 **5 个 epoch**（模拟 Day 1 / Day 3 / Day 7 / Day 14 / Day 30）：

```
Epoch 0 (Day 1):  原始场景，机器人首次深度探索建图
Epoch 1 (Day 3):  小幅变化 — 2-3个HRO移位，1个NO新增
Epoch 2 (Day 7):  中等变化 — 4-5个HRO移位，1个LRO首次移动，1个DO消失
Epoch 3 (Day 14): 较大变化 — HRO继续移位，1个LRO恢复原位或移到另一位置
Epoch 4 (Day 30): 综合变化 — HRO形成"习惯模式"（在2-3个固定点循环），新增NO
```

每个 epoch 对应一个 `layout_T{i}.json` 文件，记录该时刻所有物体的 `{obj_id, label, pos_3d, room_id, change_type}`。

### 2.4 物体移动的具体实现方式

基于你已有的 A_new_bench 工具链：

```
Step 1: export_scene_info.py → 导出场景所有房间/可放置区域
Step 2: 人工定义 "变更脚本" change_script.yaml:
        - obj: "chair_03"
          type: HRO
          positions:  # 该物体在各epoch的位置
            T0: {room: "living_room", pos: [2.1, 0.5, -3.4]}
            T1: {room: "dining_room", pos: [5.2, 0.5, -1.8]}  
            T2: {room: "living_room", pos: [2.3, 0.5, -3.2]}  # 回到附近
            T3: {room: "bedroom",     pos: [8.1, 0.5, -6.0]}
            T4: {room: "living_room", pos: [2.1, 0.5, -3.4]}  # 归位
Step 3: sample_and_place_objects.py → 对每个epoch生成场景配置
Step 4: test_layout.py → 人工微调确保物理合理性（不穿模）
Step 5: 导出每个epoch的GT标注
```

**关键约束——移动必须物理合理**：
- HRO 的"常驻点"应在合理房间（椅子不应出现在浴室）
- 使用 `query_rooms_for_objects.py` (Qwen3-VL) 生成合理的房间候选
- 位置必须在 navmesh 可达区域附近（`is_navigable_at()` 验证）

### 2.5 数据集分难度等级

| 难度 | 名称 | 场景特点 | 变化强度 |
|------|------|---------|---------|
| **Easy** | 单房间/小户型 | 1-2 个房间，物体少 (~20) | 仅 SO + 2-3 个 HRO |
| **Medium** | 标准公寓 | 4-6 个房间，物体适中 (~50) | SO + LRO + HRO + 1 DO |
| **Hard** | 大户型/多楼层 | 8+ 个房间或多楼层，物体多 (~100+) | 全五类变化，高频 HRO 有复杂"习惯模式" |

建议先从 HM3D val 中选 **3-5 个场景**（涵盖三个难度），每场景 5 个 epoch = **15-25 个 layout 配置**。

## 三、仿真实验流程设计

### 实验 1：长期记忆积累（Memory Accumulation）

**目的**：验证 C1（时序 RAG）——经过多轮探索，系统对环境的"认知"是否持续改善

**流程**：
```
for scene in scenes:
    for epoch in [T0, T1, T2, T3, T4]:
        1. 加载 layout_T{epoch}.json 修改场景物体布局
        2. 机器人执行深度探索 (Stage 1)
        3. 合并到 floors_history (时序加权融合)
        4. 对所有物体执行 GMM 查询 (不移动机器人)
        5. 计算: MRA, GHR@3, GHR@5
    绘制: MRA/GHR 随 epoch 的递增曲线
```

**预期结果**：MRA 从 E0 的 ~60% 逐步上升到 E4 的 ~90%+，体现"越记越准"

### 实验 2：动态适应（Dynamic Adaptation）

**目的**：验证 C3（负向高斯场）+ C4（三层探索） 

**流程**：
```
前提: 机器人已在 T0-T2 建立稳定记忆
在 T3 发生大规模物体移动:
    1. 对每个被移动物体发起寻物任务 (Stage 2)
    2. 记录: SSS, D-SR, 每步轨迹, 负向高斯注入次数
    3. 对比消融:
       - Full system
       - w/o 负向高斯场 (去掉 NegativeGaussianField)
       - w/o 时间衰减 (所有 epoch 等权)
```

**预期结果**：
- Full system 的 D-SR >> w/o NegGMM（证明"记仇"机制有效避免重复去旧位置）
- Full system 的 SSS 显著低于 w/o 时间衰减（证明近期信息权重更高有效）

### 实验 3：Agent-RAG 权重转换（Weight Transition）

**目的**：验证 C5（动态权重融合）

**流程**：
```
在同一场景不同探索轮次测试:
    Round 1 (首次): w_agent 高 → Agent 主导
    Round 3:        过渡期
    Round 5+:       w_rag 高 → RAG 主导
    
    每轮: 分别记录 Agent 通道 vs RAG 通道对最终 Top-1 命中的贡献
    计算: FR-Acc (Agent首选房间准确率) vs MRA (RAG位置准确率)
```

**预期结果**：
- Round 1 时 Agent 的 FR-Acc > RAG 的 MRA（先验知识救急）
- Round 5 时 RAG 的 MRA >> Agent 的 FR-Acc（历史记忆更可靠）
- 融合系统全程优于单通道

### 实验 4：盲预测与记忆保持（Blind Prediction & Retention）

**目的**：验证 C1 的深层价值——不做新探索，纯靠历史记忆预测当前物体分布

**流程**：
```
使用 5-epoch 完整数据:
    1. 让系统经历 T0-T3 的完整探索
    2. 在 T4 之前，不做新探索，不给 GT，让系统预测:
       - 每个物体当前最可能在哪？(GMM Top-1)
    3. 与 T4 的 GT 对比:
       - MRA@T4_blind (盲预测准确率)
       - MRR: 按 stability 类别分组统计保持率
         (SO 应 >90%, LRO/HRO 应逐步下降)
```

**预期结果**：
- SO 的 MRR > 90%（高稳定物体记忆保持良好）
- HRO 的 MRA@T4_blind 仍因多峰 GMM 覆盖而保持 >50%
- 整体 MRA@T4_blind >> 单次建图基线（证明累积记忆的价值）

关于是否有其他硬核指标，我认真想了一轮，结论是**现有指标体系已经覆盖了你系统能实际计算的核心维度**：

| 维度 | 已有指标 | 覆盖的系统能力 |
|------|---------|--------------|
| 记忆准确性 | MRA, GHR@K | 地图记得准不准 |
| 动态应对 | D-SR, SSS, AS | 物体移了还能不能找到、多快适应 |
| 记忆保持 | MRR | 时间衰减机制是否合理 |
| Agent 贡献 | FR-Acc | LLM 先验的兜底效果 |

**我能想到的一个补充方向**是 **NDA (Negative Disappearance Accuracy)**——针对 DO（消失物体）：机器人经过原位置、未检测到该物体后，系统是否正确将其 `exist_prob` 降到阈值以下。公式：

$$NDA = \frac{|\{o \in DO : exist\_prob(o) < \tau_{absent}\}|}{|DO|}$$

它验证的是你 `exist_prob 衰减` 机制的反面——系统不仅要记住"东西在哪"，还要学会"东西没了"。这和 MRA/D-SR 形成互补（那些测"找到"，这个测"确认不在"）。

但这个指标有一个前提：你的数据集里 DO 类物体够多（至少 3-5 个/场景）才有统计意义。如果 DO 类物体太少，这个指标就变成了噪声。

**我的建议**：先不加新指标，用现有 6 个（MRA, GHR@K, D-SR, SSS, AS, MRR）+ 2 个传统（SR, FR-Acc）跑通实验，如果审稿人提出"你系统能处理物体消失吗"，再把 NDA 作为 rebuttal 补充。指标太多反而稀释论文焦点。
