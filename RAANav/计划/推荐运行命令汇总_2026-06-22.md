本文档记录当前项目中建议在命令行执行的常用命令。默认从项目根目录运行：

```bash

```

其中真实 Habitat 闭环相关命令建议在工作站的 `habitat` 环境中执行；远程视觉服务相关命令建议在服务器的 PyTorch/CUDA 环境中执行。

## 4. 长期真实闭环 Smoke Test

只跑一个 scene、一个 layout、一个 episode，用于确认真实 Habitat + 远程视觉 + 动态 layout + scene memory + benchmark 评测主链路能跑通。

这条命令不是正式实验命令，而是“最小真实闭环”验证命令。它的意义是：在真实 Habitat-Sim 环境中加载一个动态家庭布局，让 agent 通过远程视觉服务进行多视角观测，把检测到的物体写入长期记忆，然后根据记忆候选进行导航搜索，最后用 benchmark 的真实 geodesic 路径评估结果。只要该命令能稳定跑完，就说明后续单 scene 时间序列实验和 val split 实验具备基础运行条件。

```bash
python -m RAANav.AgenticRAG.benchmark_adapter.run_temporal_habitat_loop \
  --split-manifest benchmark/splits/benchmark_split_longterm_v1.json \
  --split val \
  --scene 00808-y9hTuugGdiq \
  --layout-limit 1 \
  --episodes-per-layout 1 \
  --output-dir benchmark/eval/longterm_habitat_loop_smoke \
  --max-steps-per-subtask 20 \
  --max-rounds 2 \
  --micro-steps-per-round 4 \
  --n-views 4 \
  --clip-min-score 0.15 \
  --target-name-map RAANav/AgenticRAG/config/target_name_map_longterm_v1.json \
  --normalize-target-names \
  --target-confirmation-mode spatial \
  --target-confirmation-margin 1.0 \
  --perception-backend remote \
  --remote-vision-base-url http://127.0.0.1:50220 \
  --load-layout-objects \
  --no-euclidean-fallback
```

### 4.1 这条命令执行了什么

程序入口是 `RAANav.AgenticRAG.benchmark_adapter.run_temporal_habitat_loop`。执行时会完成以下任务：

1. 读取 `benchmark_split_longterm_v1.json`，从 `val` split 中筛选指定 scene 的 episode。
2. 按 `layout-limit=1` 和 `episodes-per-layout=1` 只保留一个动态 layout、一个 episode，形成最小 smoke test。
3. 启动 Habitat-Sim，加载 HM3D 场景和该 episode 对应的动态 layout。
4. 若指定 `--load-layout-objects`，把动态 layout 中的物体加载进 Habitat 场景，而不是只使用原始静态场景。
5. 调用远程视觉服务 `http://127.0.0.1:50220`，对 RGB 观测进行 GroundingDINO 检测、MobileSAM 分割和 CLIP embedding 计算。
6. 每一轮在当前位置做 `n_views=4` 的环视观测，把检测结果投影到 3D/2D 世界坐标，并更新 scene-level memory。
7. 根据当前 subtask 的目标描述，从 memory 中检索候选物体，并融合 label、CLIP 相似度、时间/记忆分数等信息进行排序。
8. 选择最高分候选作为导航目标，使用 Habitat navmesh 规划路径并执行若干 micro steps。
9. 如果到达候选位置后仍未检测到目标，会记录 negative feedback，降低该旧候选后续权重。
10. episode 结束后输出轨迹、候选、观测、记忆更新、负反馈和 benchmark 指标。

### 4.2 参数逐项解释

`python -m RAANav.AgenticRAG.benchmark_adapter.run_temporal_habitat_loop`  
以 Python module 方式启动长期闭环评测入口。相比直接运行 `.py` 文件，这种方式能更稳定地处理项目包路径。

`--split-manifest benchmark/splits/benchmark_split_longterm_v1.json`  
指定 benchmark split 清单。该 JSON 描述 train/val/test 等 split 对应的 episode 根目录，是程序找到长期评测任务的入口。

`--split val`  
选择 `val` split。当前 smoke test 用验证集任务检查流程是否跑通，不用于训练。

`--scene 00808-y9hTuugGdiq`  
只筛选这个 HM3D scene 下的 episode。长期能力评测的核心是“同一家庭环境多时间状态”，因此 smoke test 固定一个 scene，先检查单家庭链路。

`--layout-limit 1`  
只取该 scene 的第 1 个 layout。动态数据集中同一 scene 可能有多个 layout/state，该参数把运行范围压缩到最小，便于快速定位工程问题。

`--episodes-per-layout 1`  
每个 layout 只跑 1 个 episode。与 `--layout-limit 1` 配合后，最终只跑 1 个 episode。

`--output-dir benchmark/eval/longterm_habitat_loop_smoke`  
指定输出目录。程序会在这里写入 `run.jsonl`、`summary.json`、`candidate_traces.jsonl`、`observation_traces.jsonl`、`memory_updates.jsonl`、`negative_feedback.jsonl` 等诊断文件。

`--max-steps-per-subtask 20`  
每个 subtask 最多允许执行 20 个导航 micro steps。smoke test 中该值偏小，主要用于快速验证程序不崩；正式实验建议提高到 `40`、`80` 或按任务难度继续增大。

`--max-rounds 2`  
每个 subtask 最多进行 2 轮“观测 -> 检索候选 -> 导航 -> 再观测”。如果目标未发现且轮数用完，该 subtask 结束。

`--micro-steps-per-round 4`  
每一轮最多沿规划路径前进 4 个 micro steps。它决定每轮导航推进的距离上限，和 `--max-rounds` 共同限制总搜索预算。

`--n-views 4`  
每次观测在当前位置做 4 个视角的环视，通常对应每 90 度采集一次 RGB-D。该参数越大，感知覆盖越完整，但远程检测调用次数和耗时也会增加。

`--clip-min-score 0.15`  
远程 CLIP text-image 相似度候选的最低分数。降低该阈值可以提高召回，但也可能引入更多误候选；建议结合 `candidate_traces.jsonl` 和 `temporal_run_diagnosis.json` 判断是否真正提升 `GHR@3/GHR@5` 和 `found_rate`。

`--target-name-map RAANav/AgenticRAG/config/target_name_map_longterm_v1.json`  
指定目标名称映射表，用于把数据集目标名映射到更容易被开放词汇检测器识别的标签。例如 `chess_set -> chess`、`camera_01 -> camera`、`alarm_clock_01 -> alarm_clock/clock`。

`--normalize-target-names`  
启用内置目标名规范化和 alias 匹配。即使不指定 `--target-name-map`，也会启用内置规则；显式指定映射文件便于实验记录和后续修改。

`--target-confirmation-mode spatial`  
使用空间一致的目标确认逻辑。即检测 label 匹配后，还需要检测位置接近 benchmark subtask 的真实目标位置，才认为目标被确认。该参数用于避免仅凭同名或近义 label 误判目标已发现。

`--target-confirmation-margin 1.0`  
空间确认时在 `success_radius` 外额外放宽 1.0 米，用于容忍深度投影和检测中心点误差。如果该值过大，可能重新引入误确认；如果过小，可能漏掉真实目标。

`--perception-backend remote`  
使用远程感知后端。当前真实闭环主线依赖服务器侧 GroundingDINO、MobileSAM 和 CLIP，工作站只负责 Habitat 渲染、导航和评测。

`--remote-vision-base-url http://127.0.0.1:50220`  
远程视觉服务在工作站侧可访问的地址。这里的 `127.0.0.1:50220` 通常是 SSH tunnel 的本地端口，实际请求会被转发到服务器上的视觉服务端口，例如 `127.0.0.1:8010`。

`--load-layout-objects`  
把动态 layout 中定义的物体加载进 Habitat 场景。这是长期动态家庭评测的关键参数；如果不加，实验更接近原始 HM3D 静态场景，无法有效检验 layout/state 变化。

`--no-euclidean-fallback`  
禁用欧氏距离 fallback，强制使用 Habitat navmesh/geodesic 路径进行导航和评估。正式评测建议保留该参数，避免用直线距离得到虚高或失真的结果。

### 4.3 输出文件说明

运行成功后，重点检查：

```bash
cat benchmark/eval/longterm_habitat_loop_smoke/summary.json
cat benchmark/eval/longterm_habitat_loop_smoke/temporal_summary.json
cat benchmark/eval/longterm_habitat_loop_smoke/perception_summary.json
head -n 20 benchmark/eval/longterm_habitat_loop_smoke/candidate_traces.jsonl
head -n 20 benchmark/eval/longterm_habitat_loop_smoke/observation_traces.jsonl
head -n 20 benchmark/eval/longterm_habitat_loop_smoke/memory_updates.jsonl
head -n 20 benchmark/eval/longterm_habitat_loop_smoke/negative_feedback.jsonl
```

也可以使用诊断脚本自动汇总：

```bash
python -m RAANav.AgenticRAG.benchmark_adapter.diagnose_temporal_run \
  --output-dir benchmark/eval/longterm_habitat_loop_smoke \
  --write-json benchmark/eval/longterm_habitat_loop_smoke/temporal_run_diagnosis.json
```

其中：

- `summary.json`：benchmark 总指标，包括 SR、SPL、平均步数、平均路径长度、最短路径长度、动态记忆准确率。
- `temporal_summary.json`：按 `state_index` 和 `seen_layout_count_before` 聚合的长期能力指标。
- `perception_summary.json`：远程视觉调用次数、失败次数、检测总数和平均耗时。
- `candidate_traces.jsonl`：每轮检索出的候选、最终选择的候选、fallback 原因、规划位置和移动结果。
- `observation_traces.jsonl`：每次环视检测到的 label、bbox、位置、CLIP embedding 维度等。
- `memory_updates.jsonl`：scene memory 中物体轨迹的新建、合并、迁移等事件。
- `negative_feedback.jsonl`：到达候选后仍未发现目标时产生的负反馈记录。
- `temporal_run_diagnosis.json`：诊断脚本生成的汇总报告，会给出失败归因，例如 `retrieval_no_candidates`、`candidates_far_from_goal`、`candidate_near_but_navigation_or_success_radius_failed`。

### 4.4 如何解读 smoke test 结果

如果命令退出码为 `0`，并且 `perception_summary.json` 中 `failures=0`、`detections>0`，说明真实 Habitat 渲染、远程视觉和记忆更新主链路基本正常。

`success_rate=0.0` 不一定表示系统不可用。smoke test 的搜索预算很小，且只跑一个 episode，更适合判断工程链路是否跑通。需要结合诊断文件继续判断：

- 如果 `candidate_traces.jsonl` 中经常没有候选，优先检查 CLIP/text-image 检索、目标 label、alias 和 memory 更新。
- 如果候选存在但 `min_dist` 很大，说明候选排序或长期记忆位置还没有学到目标区域。
- 如果候选接近目标但最终失败，优先增加 `--max-steps-per-subtask`、`--max-rounds` 或检查成功半径与最终观测确认逻辑。
- 如果 `observation_traces.jsonl` 中检测数量很少，优先检查远程视觉服务、检测阈值、prompt label 列表和视角覆盖。

正式检验长期能力时，不应只看这一条 smoke test，而应继续运行“单 Scene 时间序列验证”和“Val Split 完整运行”，观察 `seen_layout_count_before` 增加时 SR/SPL、found rate、GHR@3/GHR@5 是否提升。

如果 `summary.json` 中 `success_rate=0.0`，但 `episodes`、`evaluated_episodes`、`trajectory_count` 一致且 `missing_episode_count=0`，说明工程闭环已经跑通，下一步应查看 `temporal_run_diagnosis.json` 中的 `failure_bucket`。常见含义：

- `retrieval_no_candidates`：memory 中没有形成可用候选，应检查观测、CLIP embedding、目标 label/alias。
- `candidates_far_from_goal`：候选存在但离真实目标远，应检查融合评分和历史记忆是否学习到目标迁移。
- `perception_goal_mismatch_or_false_positive_confirmation`：感知层多次认为看见目标，但最终 benchmark 位姿没有进入成功半径，应检查 label 误匹配、同类物体误检和空间确认逻辑。
- `candidate_near_but_navigation_or_success_radius_failed`：候选接近目标但没有达成成功，应增加步数预算或检查成功半径、最终观测确认。
- `perception_empty` 或 `memory_not_updated`：远程感知或深度投影/记忆写入链路异常。

## 12. 常见问题定位

### 远程服务不可用

```bash
curl http://127.0.0.1:50220/health
```

如果失败，先检查 SSH tunnel 或服务器端 `remote_vision_server/run_server.sh` 是否正在运行。

### Habitat 或 navmesh 问题

真实闭环建议使用：

```bash
--load-layout-objects --no-euclidean-fallback
```

如果报 Habitat 初始化失败，优先检查：

```bash
python -c "import habitat_sim; print('habitat_sim ok')"
```

### CLIP 离线模型问题

服务器端应设置：

```bash
export REMOTE_VISION_CLIP_MODEL_PATH=/home/ma-user/work/zhangWei/mtu3d/data/trans/clip-vit-large-patch14
export REMOTE_VISION_CLIP_LOCAL_FILES_ONLY=1
```

### GroundingDINO ops 问题

服务器端检查：

```bash
python -c "import groundingdino._C; print('GroundingDINO ops ok')"
```

如果出现 `libc10.so` 找不到，检查 PyTorch 动态库路径：

```bash
python -c "import torch, os; print(os.path.join(os.path.dirname(torch.__file__), 'lib'))"
```

然后将该路径加入 `LD_LIBRARY_PATH`。
