# 当前项目算法逻辑与选点导航策略总结

日期：2026-07-01

本文参考 `AgenticRAG_可执行技术规范_v1.md`，并结合当前工程中的长期 benchmark 闭环实现，总结项目的整体算法流程。重点说明当前系统如何从感知结果构建长期记忆，如何检索候选目标，以及如何把候选目标转化为 Habitat 中的导航选点。

## 1. 项目目标

本项目面向同一家庭环境下的长期目标搜索与导航任务。核心问题不是单次在静态场景中找物体，而是在同一 scene 的多个时间状态、多个动态 layout 中，让 agent 利用历史观察、目标语义、图像检索和长期记忆，提高后续寻找目标物体的效率与成功率。

算法主线可以概括为：

```text
动态 layout episode
  -> Habitat RGB-D 环视观测
  -> 远程开放词表感知 GroundingDINO + MobileSAM + CLIP
  -> 深度反投影得到物体 3D / 2D 位置
  -> SceneMemory 更新长期 object track 与 pseudo-room memory
  -> 根据目标 query 检索和评分候选物体
  -> 选择最优候选点或 fallback 探索点
  -> Habitat navmesh 规划并步进移动
  -> 到达后再次观测、确认目标、写入正负反馈
  -> 跨 layout / state_index 持续积累同一 scene 的记忆
```

## 2. 输入数据与任务组织

当前长期评测入口以 benchmark episode 为中心，而不是单次手写目标导航。每个 episode 通常包含：

- `scene_name`：家庭场景 ID，例如 `00808-y9hTuugGdiq`。
- `layout_id`：动态布局 ID。
- `state_index`：时间状态索引，表示同一家庭环境在不同时刻的状态。
- `seen_layout_count_before`：当前 episode 前 agent 已经看过多少个 layout，用于衡量长期经验积累。
- `subtasks`：具体目标任务，可能是 open-vocabulary、image-goal 或 language-goal。

当前主要闭环脚本为：

```bash
python -m RAANav.AgenticRAG.benchmark_adapter.run_temporal_habitat_loop
```

该脚本会按 scene、state_index、layout_id、episode_id 排序执行任务，使同一 scene 的记忆能够跨 layout 延续。

## 3. Query 构建与目标名称归一化

每个 subtask 会被转换为统一的 `RetrievalQuery`。Query 中包含：

- 目标标签或目标对象名。
- 目标对象实例 ID。
- image-goal 图片路径。
- language-goal 文本描述。
- alias labels。
- sampled region / target instance 等 layout 元数据。

当前工程支持目标名称映射与归一化：

```bash
--target-name-map RAANav/AgenticRAG/config/target_name_map_longterm_v1.json
--normalize-target-names
```

名称归一化的作用是缓解数据集目标名、模型检测标签和人工语义名称之间的不一致。例如 episode 中可能出现较具体的模型名或资产名，而检测模型更可能输出通用物体类别。归一化后，系统会尽量把这些名字映射到更稳定的查询标签集合。

## 4. 感知链路

当前系统的视觉感知主要由远程服务器完成，工作站负责 Habitat 仿真和导航闭环。

### 4.1 Habitat 环视观测

在每个查询 round 中，agent 会在当前位置执行多视角环视：

```bash
--n-views 4
```

通常表示每个位置采集 4 个方向的 RGB-D 图像。每张图像会送入远程感知服务。

### 4.2 远程开放词表感知

远程服务器负责：

- GroundingDINO：根据文本 prompt 检测开放词表物体。
- MobileSAM：对检测框进行分割。
- CLIP image embedding：为 crop 或 mask 区域生成图像 embedding。
- CLIP text-image similarity：用同一 CLIP 模型计算 query text 与候选图像 embedding 的相似度。

工作站通过 HTTP 或 SSH tunnel 调用远程服务：

```bash
--perception-backend remote
--remote-vision-base-url http://127.0.0.1:50220
```

### 4.3 深度反投影

远程感知返回 2D 检测框、mask、label、score 和 CLIP embedding 后，工作站会结合 Habitat 深度图估计物体世界坐标：

1. 优先使用 mask 内有效深度的中位数。
2. 若 mask 不可靠，则使用 bbox 中心深度。
3. 根据相机内参把像素点反投影到 camera frame。
4. 再根据 agent 当前位姿转换到 world frame。
5. 写入检测结果中的 `pos_3d` 与 `pos_2d`。

其中 `pos_2d` 通常使用水平平面上的 `(x, z)` 坐标，是后续检索、选点和可视化的核心空间坐标。

## 5. 长期记忆地图构建

当前长期记忆核心为 `SceneMemory`。它维护同一 scene 下的全局 object tracks，并在此基础上增加 pseudo-room 级索引。

### 5.1 Object Track

每个 object track 对应一个长期记忆中的候选物体，记录：

- `obj_id`
- `label`
- `pos_3d / pos_2d`
- `clip_embedding`
- `last_seen_state_index`
- `last_seen_layout_id`
- `seen_count`
- `miss_count`
- `exist_prob`
- `stability`
- `negative_feedback_count`
- `cooccur_stats`

当新检测到一个物体时，系统会尝试与已有 track 合并：

- 若标签归一化后一致，且空间距离较近，则执行 `merged`。
- 若标签一致但位置变化较大，且仍在迁移距离阈值内，或 CLIP 相似度足够高，则执行 `migrated`。
- 若无法匹配，则创建新 track，事件为 `new`。

当前默认合并相关阈值包括：

- `merge_distance = 0.75m`
- `migration_distance = 4.0m`
- `clip_migration_threshold = 0.92`

### 5.2 RoomMemory

当前第一版房间记忆采用 deterministic pseudo-room，而不声称是真实语义房间。其目的是先让系统具备“房间级长期证据”的结构。

默认 pseudo-room 分配方法：

```text
room_id = pseudo_room_<floor(x / grid_size)>_<floor(z / grid_size)>
grid_size = 4.0m
```

每个 room 保存：

- `room_id`
- `room_label`
- `object_refs`
- 每个 object 在该 room 内的证据：
  - `seen_count`
  - `room_exist_prob`
  - `positions_2d`
  - `last_seen_state_index`
  - `negative_count`

Object 本身不会被复制到多个 room。RoomMemory 只保存 object 引用和房间级证据，ObjectTrack 仍是全局唯一。

### 5.3 Room Belief 更新

每次 object 被观测到后，系统会更新其房间信念：

- 当前观测 room 的 belief 增加。
- 其他 room 的 belief 轻微衰减。
- `current_room_id` 更新为当前最大信念或最近观测 room。
- `room_history` 追加 `new / merged / migrated / negative_feedback` 等事件。

若一个候选点被访问后没有发现目标，则系统会记录 negative feedback：

- object 的 `exist_prob` 降低。
- 当前 room 的 `room_belief` 降低。
- RoomObjectEvidence 的 `negative_count` 增加。

这使得 agent 后续不会一直固执地回到已经失败的位置或房间。

## 6. 候选生成逻辑

每个 round 中，系统先用当前 SceneMemory 生成候选集合。候选来自所有带空间坐标的 object tracks。

候选生成不是只依赖标签精确匹配，而是综合以下信息：

- 目标名称与 object label 的匹配。
- query alias 与 object label 的匹配。
- image-goal / text-goal 与 object CLIP embedding 的相似度。
- object 与目标实例、采样区域、历史共现关系的关联。
- object 的时间新鲜度、稳定性和存在概率。
- Agent prior，也就是基于语义、区域和任务元数据得到的启发式先验。

当前系统在远程 CLIP 可用时，会调用服务器端 CLIP text-image similarity 对 memory 中已有 object embedding 做重排序或补充。

## 7. 候选评分公式

技术规范中 Agentic-RAG 的核心思想是把 RAG 检索分数、时间衰减、稳定性、共现置信度和 Agent 先验进行融合。当前工程实现中的主要评分逻辑如下。

### 7.1 语义相似度 `R_sim`

`R_sim` 衡量 query 与 object 的语义或图像相似度：

- 若目标实例 ID 与 object ID 精确一致，则 `R_sim = 1.0`。
- 若 query label 与 object label 命中，则通常提升到约 `0.95`。
- 若启用远程 CLIP，则使用 text-image cosine similarity。
- 若没有 CLIP，则退化为标签相似度或 token overlap。

### 7.2 共现与关系置信度 `R_cfd`

`R_cfd` 衡量 object 与目标之间是否存在上下文关系。当前实现中主要来自：

- 是否同一 target instance。
- 是否同一 sampled region。
- 是否存在显式共现统计。
- 数据集元数据中的关联字段。

### 7.3 时间稳定门控 `G_ts`

时间衰减用于表达动态环境中的记忆过期：

```text
G_ts = exp(-(lambda * DeltaT) / (1 + kappa * stability))
```

其中：

- `DeltaT` 表示当前 state_index 与 object 上次观测 state_index 的差。
- `stability` 越高，衰减越慢。
- 动态物体如果很久没有被观测到，其历史位置分数会下降。

### 7.4 RAG 分数 `S_rag`

```text
S_base = beta1 * R_sim + beta2 * R_cfd
S_rag = S_base * G_ts * exist_prob
```

其中：

- `exist_prob` 表示当前 object 仍然存在于该位置或该 room 的概率。
- negative feedback 会显著降低 `exist_prob`。

当前默认权重接近：

```text
beta1 = 0.65
beta2 = 0.35
```

### 7.5 Agent 先验 `S_agent`

Agent 先验用于在检索证据不足时提供语义和任务层面的补充。当前实现主要是启发式 prior，而不是完整在线 LLM 推理。

`S_agent` 会考虑：

- label 是否匹配目标。
- query 与 object label 是否有 token overlap。
- 是否处于同一 sampled region。
- 是否与 target instance 相关。
- 是否存在 language prompt。

### 7.6 动态融合

最终分数：

```text
S_final = w_rag * S_rag + w_agent * S_agent
```

其中：

```text
w_agent = max(w_min, exp(-k * round_index))
w_rag = 1 - w_agent
```

含义是：

- 早期 round 中，Agent 先验权重更高，用于快速给出方向。
- 随着探索进行，真实感知和记忆证据逐渐占主导。
- `w_min` 保证 Agent 先验不会完全消失。

当前默认近似为：

```text
k = 0.35
w_min = 0.15
```

## 8. 选点导航策略

选点导航策略是当前闭环系统的关键。它回答两个问题：

1. 下一步应该去哪里？
2. 如果去过之后没有找到目标，下一轮如何调整？

### 8.1 每轮导航的基本流程

对每个 subtask，系统会执行最多 `max_rounds` 轮。每轮流程如下：

```text
当前位置环视观测
  -> 更新 SceneMemory
  -> 判断是否已经看到目标
  -> 从 SceneMemory 中检索候选 object
  -> 计算每个候选的 S_final
  -> 按 S_final 排序并去重
  -> 选择排名第一的候选作为本轮导航目标点
  -> 若无候选，则选择 fallback 探索点
  -> Habitat navmesh 规划到目标点
  -> 只执行有限 micro-steps
  -> 到达或中途停止后再次观测
  -> 若仍未找到目标，对已访问候选写入 negative feedback
```

这是一种“闭环 receding-horizon”策略：每次只计划到当前最优候选附近，并执行有限步数；移动后重新感知、重新更新记忆、重新评分，而不是一次性规划完整全局路径。

### 8.2 候选点如何转成导航点

每个候选 object 都有世界坐标：

```text
candidate.pos_2d = (x, z)
```

系统会将其转换为 Habitat 目标 pose：

```text
target_pose = [candidate.x, current_y, candidate.z]
```

也就是说，候选物体的水平位置直接作为本轮导航目标点。高度通常沿用 agent 当前高度或由 Habitat snap 处理。

### 8.3 Top-1 候选选择

当前实现中，实际导航选点采用 Top-1 策略：

```text
selected_candidate = argmax S_final(candidate)
```

并把该 candidate 的位置作为本轮导航目标。Top-K 候选不会同时执行，而是用于：

- 诊断与可视化。
- GHR@K 等指标计算。
- 当后续 round 中 Top-1 被负反馈压低后，其他候选可能升为 Top-1。

候选排序后还会执行空间去重，避免多个几乎重合的 object track 重复占据候选列表。当前去重半径约为：

```text
dedup_radius = 0.25m
```

### 8.4 远程 CLIP 对选点的影响

远程 CLIP text-image similarity 会改变候选排序：

1. 对 memory 中已有 image embedding 的物体计算 query text 相似度。
2. 若 similarity 超过 `--clip-min-score`，则提升或补充候选。
3. 候选的 `sim_backend` 会标记为 `remote_clip_text_image`。

因此，降低 `--clip-min-score` 会增加候选召回，但也可能引入更多误匹配。实际调试中常用阈值包括：

```text
0.15, 0.30, 0.50, 0.65, 0.70, 0.75, 0.80, 0.85
```

对于成功率为零的早期实验，低阈值有利于确认闭环是否能产生候选；正式评测中需要通过候选可视化和 top-k similarity 分布重新校准。

### 8.5 无候选时的 fallback 选点

若当前 memory 中没有任何可用候选，系统不会停止，而是执行 fallback 探索。

当前 fallback 逻辑大致为：

- 若 Habitat simulator 不可用，则在当前位置附近生成随机偏移点。
- 若 Habitat simulator 可用，则从 navmesh 中采样一个随机可导航点。

fallback 的意义是让 agent 继续探索并积累感知，而不是在无候选时直接失败。

但是 fallback 不具备强目标导向，因此如果候选长期为空，导航会接近随机探索。此时应重点检查：

- 远程感知是否有 detections。
- detections 是否有 `pos_2d`。
- memory 是否被更新。
- target name map 是否正确。
- CLIP similarity 是否过低或阈值过高。

### 8.6 Navmesh 规划与步进执行

选定目标点后，系统不会直接瞬移，而是交给 Habitat navmesh 做真实路径规划：

1. 将候选点 snap 到可导航区域。
2. 调用 Habitat pathfinder 计算 shortest path points。
3. 根据 `micro_steps_per_round` 截断路径。
4. agent 沿路径逐点移动。
5. 记录实际路径长度、步数和最终位置。

对应命令参数：

```bash
--micro-steps-per-round 8
--max-steps-per-subtask 80
--no-euclidean-fallback
```

其中：

- `micro-steps-per-round` 控制每轮最多走多少个微步。
- `max-steps-per-subtask` 控制一个 subtask 的总步数上限。
- `--no-euclidean-fallback` 要求使用真实 geodesic / navmesh 结果，避免用欧氏距离替代路径导致评估失真。

### 8.7 到达后确认目标

移动后系统会再次环视观测。目标确认通常有两种思路：

- label / alias 模式：检测标签与目标 query 匹配即可。
- spatial 模式：检测标签匹配，并且检测位置接近 benchmark 中的目标真值位置。

常用参数：

```bash
--target-confirmation-mode spatial
--target-confirmation-margin 1.0
```

spatial 模式更严格，适合 benchmark 评估，因为它避免了只看到同类物体就误判成功。

### 8.8 Negative Feedback 如何影响下一轮选点

如果系统导航到了 Top-1 候选附近，但后续观测没有确认目标，就会对该候选写入负反馈：

```text
candidate_reached_target_not_detected
```

负反馈会导致：

- object `exist_prob` 降低。
- `miss_count` 增加。
- `negative_feedback_count` 增加。
- 当前 room 的 `room_belief` 降低。
- room evidence 的 `negative_count` 增加。

下一轮评分时，`exist_prob` 会进入 `S_rag`：

```text
S_rag = S_base * G_ts * exist_prob
```

因此失败过的位置分数会下降，其他候选或其他 room 的候选更容易被选中。这是长期动态环境中避免重复搜索旧位置的关键机制。

### 8.9 与技术规范中 GMM 选点的关系

技术规范中理想的 Agentic-RAG 会把候选 object 转换为空间概率场：

```text
P(x, y | q, t) = sum_i S_i * Gaussian((x, y), mu_i, Sigma_i)
```

然后从概率场中选择 Top-K peak 作为探索点，同时可叠加 negative Gaussian 抑制失败区域。

当前 benchmark 闭环实现更偏 object-centric：

- 直接对 object tracks 进行评分和排序。
- 选择 `S_final` 最高的 object 位置作为导航目标。
- 通过 negative feedback 降低失败候选的未来分数。

也就是说，当前系统已经保留了 RAG/Agent 融合评分、时间衰减、稳定性、存在概率和负反馈等核心机制，但还没有在主闭环中完整使用连续 GMM 概率场作为导航选点底图。GMM 更适合作为后续增强方向：

- 将多个相近候选融合为区域级 peak。
- 用 room belief 调整 Gaussian 权重。
- 用 negative Gaussian 形成显式搜索排斥区。
- 在候选为空时由 Agent prior 生成房间级 Gaussian，而不是完全 random fallback。

## 9. 长期能力如何体现

长期能力主要来自四个方面：

### 9.1 跨 layout 的 SceneMemory

同一 scene 的 object tracks 不会在每个 episode 后清空，而是跨 layout 和 state_index 持续更新。这使 agent 能利用之前见过的物体位置、房间分布和失败经验。

### 9.2 时间衰减

旧记忆不会永久等价于新观测。动态物体越久没被看到，其历史位置得分越低；稳定物体衰减较慢。

### 9.3 迁移事件

当同一物体或同类物体在新位置被观测到，系统会记录 `migrated`，表示它可能从旧位置迁移到了新位置。这对于动态 layout 尤其重要。

### 9.4 负反馈

如果旧位置找不到目标，系统会降低该 object 和 room 的置信度，推动后续搜索离开失败区域。

正式长期能力验证应观察：

- `seen_layout_count_before` 增加时，SR / SPL / found_rate 是否提升。
- 动态目标旧位置失败后，后续候选是否迁移到新高概率区域。
- image-goal / language-goal 是否真正利用 CLIP 和语义，而不是退化为标签匹配。

## 10. 主要输出与调试文件

一次 temporal habitat loop 通常会输出：

- `run.jsonl`：每个 episode / subtask 的轨迹与结果。
- `candidate_traces.jsonl`：每轮候选、分数、backend、top-k。
- `observation_traces.jsonl`：每步观测标签与检测统计。
- `memory_updates.jsonl`：new / merged / migrated / negative_feedback 等记忆事件。
- `negative_feedback.jsonl`：失败反馈记录。
- `layout_transitions.jsonl`：layout / state 切换记录。
- `scene_memory/<scene>/scene_memory_final.json`：最终长期记忆地图。
- `summary.json` 或 benchmark summary：SR、SPL、路径长度等最终指标。
- `visual_debug/index.html`：可视化调试页面。

调试选点策略时，最重要的是同时查看：

- 当前 subtask 的目标名称和 alias。
- 每轮候选数量。
- Top-1 candidate 的 `S_final`、`R_sim`、`S_rag`、`S_agent`。
- Top-1 的空间位置与目标真值位置距离。
- 是否频繁 fallback。
- negative feedback 是否让失败候选降权。
- memory 中是否产生有效 room belief。

## 11. 当前策略的优势与局限

### 优势

- 能在真实 Habitat navmesh 上闭环运行，而不是只做离线检索。
- 支持远程开放词表感知，工作站不需要承担重模型推理。
- 支持跨 layout 的 scene-level memory。
- 支持 CLIP text-image 检索、目标名称归一化、时间衰减和负反馈。
- 已具备 room memory 的结构基础，便于后续从 pseudo-room 升级到语义房间。

### 局限

- 当前主闭环选点仍是 object-centric Top-1，不是完整连续 GMM 概率场选点。
- 当前 Agent prior 主要是启发式融合，还不是完整 LLM 规划策略。
- pseudo-room 是固定网格，不等同于真实房间边界。
- 若远程感知召回不足或目标名称映射错误，候选会为空，策略会退化为随机 fallback。
- 若 CLIP 阈值过低，候选召回提升但误检会增多；若阈值过高，容易无候选。

## 12. 推荐的选点策略后续增强方向

为了更贴近技术规范中的 Agentic-RAG，后续可以按以下顺序增强：

1. 将当前 object candidate list 转换为显式 GMM probability field。
2. 使用 room belief 调整 Gaussian 权重，实现房间级选点。
3. 对失败区域加入 negative Gaussian，而不只是降低 object `exist_prob`。
4. 在无候选时，让 Agent prior 生成 room-level 或 receptacle-level candidate，而不是 random fallback。
5. 把 semantic region / navmesh contour 融入选点，避免选择不可达或语义不合理区域。
6. 对 Top-K 候选进行路径代价修正，例如：

```text
S_nav = S_final - alpha * normalized_geodesic_distance
```

这样可以避免总是选择语义分数高但路径代价极大的候选点。

## 13. 一句话总结

当前项目的算法本质是：在同一家庭的时间序列动态布局中，用远程开放词表视觉感知构建 scene-level 长期记忆，再用 RAG 检索分数、时间衰减、稳定性、Agent 先验和负反馈对记忆中的目标候选进行排序；导航时选择当前最高分候选的空间位置作为目标点，通过 Habitat navmesh 进行真实路径规划和步进执行，并在每轮移动后重新观测、更新记忆和调整下一轮选点。
