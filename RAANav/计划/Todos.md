    4. **可视化**：使用 Python 的 `matplotlib` 或 `seaborn`，将 GMM 得到的热力图叠加到该房间的 2D 俯视栅格地图上。

### 第五部分：不容忽视的工程盲区 (Critical Pitfalls to Watch Out)

我必须提醒你三个在开发时极容易导致系统崩溃的细节，请务必留意：

1. **GMM 高斯分布的“穿墙”灾难**：
    - 高斯分布是向四周扩散的。如果概率最高点在桌子上，高斯协方差可能会把概率扩散到墙壁里面或者墙外。
    - **解决方案**：算完 GMM 后，必须与 2D Occupancy Map（占据栅格地图，即不可通行的墙壁区域）做**掩码相乘（Masking）**。任何在墙体里的概率直接强制置零，否则机器人会试图撞墙。
2. **2D IoU 导致的三维堆叠误判**：
    - 你目前判断物体是否没变的逻辑是 2D 边界框（Region）的交并比（IoU）。如果一个杯子放在桌子上，如果只看 2D 俯视图，就算杯子被拿走，桌子的 2D bounding box 还在那里，系统容易混淆上下关系。
    - **解决方案**：在更新节点时，务必要加入 `z_range` (高度区间) 的检验，将 2D IoU 升级为 **3D 边界框重叠检验**。
3. **时间权重必须使用真实 $\Delta T$**：
    - 你的平滑公式现在用的是迭代次数 $N$。但现实中，“昨天更新的”和“一分钟前更新的”，虽然都是相差 1 次迭代，但过期概率截然不同。
    - **解决方案**：地图的 JSON 中加上真实 `timestamp`，在计算 `Rscore` 或时序衰减时引入真实时间差 $\Delta T$ （例如引入 $e^{-\lambda \Delta T}$ 作为衰减系数）。
