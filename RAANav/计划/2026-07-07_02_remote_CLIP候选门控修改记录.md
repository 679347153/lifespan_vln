## 2. 诊断结论

本轮结果说明：

1. `weak` 候选已经被有效压低，`selected_match_strength.weak = 22/488`，不再是主要问题。
2. `none` 候选仍然偏多，`selected_match_strength.none = 165/488`，说明 remote CLIP 或 text fallback 仍会把无 alias 匹配的候选推到 Top-1。
3. `GHR@10 = 0.297297` 高于 `GHR@5 = 0.189189`，说明 Top-10 中存在一定召回，但 Top-1/Top-5 排序仍弱。
4. `perception_found_rate - found_rate = 0.297297`，说明感知确认与 benchmark 成功之间仍有明显落差。
5. 当前还不适合直接实施完整 Top-K 路径代价重排序，因为候选排序质量仍受 remote CLIP 噪声影响。

阶段性判断：

```text
当前优先级不是完整导航重排序，而是先压制 remote CLIP 的 none/weak 低置信候选。
```

## 4. 具体逻辑

remote CLIP 查询文本：

```text
若 query 没有 language_prompt，默认只使用 strong_alias_labels 构造 remote CLIP text query。
weak_alias_labels 不再默认进入 remote CLIP text query。
```

候选门控：

```text
match_strength = weak:
  raw_score < remote_clip_weak_min_score 时丢弃
  分数仍受 WEAK_ALIAS_SIMILARITY_CAP = 0.35 封顶

match_strength = none:
  raw_score < remote_clip_none_min_score 时丢弃
  S_final 贡献最多为 remote_clip_none_score_cap
```


## 8. 追加执行：复合目标单 token 弱别名收紧

本轮诊断中 `selected_match_strength.none = 165/488` 偏高。进一步检查发现，部分 `none` 候选来自复合目标名称的单 token overlap，例如：

```text
alarm       vs alarm_clock
carrot      vs carrot_cake
horse       vs horse_statue
marble      vs marble_bust
wine        vs wine_bottles
side        vs side_table
brass       vs brass_pot / brass_vase
```

这些词不适合作为 strong alias，但也不应继续以 `none + token_overlap=0.5` 的形式获得偏高分数。因此已将其显式放入 weak alias，使其受到 weak alias 分数封顶和 remote CLIP weak 门控约束。

修改文件：

```text
RAANav/AgenticRAG/benchmark_adapter/episode_to_queries.py
RAANav/AgenticRAG/config/target_name_map_longterm_v1.json
```

新增或调整的 weak alias：

```text
alarm_clock_01: alarm
carrot_cake: carrot
horse_statue_01: horse
marble_bust_01: marble
wine_bottles_01: wine
side_table_tall_01: side
brass_pot_01: brass
brass_vase_03: brass
```

预期效果：

```text
selected_match_strength.none 继续下降
selected_match_strength.weak 可能小幅上升，但其分数受 0.35 cap 控制
alarm/carrot/horse/marble/wine/side/brass 不再作为 none 高分候选干扰 Top-1
```
