## 环境配置与依赖管理类

### 1. Conda 环境复制与 Pip 安装错位问题
**问题描述：**
当我们强行从终端（如 `conda run -p /path/to/env pip install xxx`）安装某个依赖包，却在另一个环境查出 `ModuleNotFoundError`。或者在复制已有的隔离环境（例如从 `sem-map` 到 `agentrag`）时发生模块混乱。

**根本原因：**
使用 `conda run`、`conda activate` 或环境别名有时会因为终端缓存、不完全的环境变量迁移、或者遗留在原本依赖内的 `shebangs` (如已缓存的旧 pip 文件首行路径) 导致 Pip 把新包偷偷安装回原来的 conda 目录。

**解决方案结论：**
不要过度信任虚拟环境内部调用的各种别名和脚本快捷方式（特别是在非干净基础之上执行时）。
**一定要强制声明绝对路径：调用特定环境中完全绑定的解释器去装依赖！**
错误示例：
`conda run -p /home/user/myenv pip install package`
正确示例：
`/home/user/myenv/bin/python -m pip install package`
这样做可以保证 Python 强制从当前路径下加载依赖规则，从而保证写入当前的 `site-packages`。

### 2. 大型预训练模型下载失效或卡死
**问题描述：**
国内连接 Hugging Face 往往被墙，使用标准 `wget` 后经常被阻塞或者下下停停（有时还会只下载一个空文件导致 wget 重试认为下载好而报错绕过）。
**正确处理途径：**
1. 获取时加上 `-c`（断点续传）和 `-nc` (若不存在则下)。
2. 通过国内镜像源下载替代官方源。
   例如将 `https://huggingface.co/laion/...` 替换为 `https://hf-mirror.com/laion/...`
   注意如果已生成了半截的空文件，记得先用 `rm` 清理掉否则镜像重下也会被忽略。
