
## 讨论：下一步实验方案

### 1. 完整仿真探索建图 + 可视化

当前 sim_nav_loop.py 存在的核心问题：**观测使用 GT semantic sensor（一帧看穿全场），不旋转，CLIP 索引不随地图增长更新**。

**改造方案**：

```
当前:  GT semantic → AABB center → Object → merge
目标:  RGB-D 帧 → 检测/分割模型 → 深度投影3D → Object → merge
```

分两步走：
- **Phase 1 (Sim2Sim)**: 在 Habitat 里取 RGB-D 帧 → 接 GroundedSAM / YOLO-World open-vocab 检测 → 深度图反投影得 3D 位置 → 构建 Object。**仍在仿真中，但感知链路和真机一致**。这步能复用 `HabitatAgent.observe()` 返回的 `rgb` + `depth` 通道。
- **Phase 2 (加旋转)**: Agent 每步做 4 方向旋转观测 (0°/90°/180°/270°)，合并为 panoramic observation。解决单视角遗漏。

**可视化**需要加的输出（每步保存到 `step_N/`）：
| 输出 | 内容 |
|------|------|
| `rgb.png` | 当前 RGB 视角 |
| `depth.png` | 深度图 (colorized) |
| `detection.png` | 检测框叠加在 RGB 上 |
| `map_incremental.png` | 当前地图截面 + 新增物体高亮 |
| `trajectory_live.png` | 到当前步的轨迹 |
| `prob_field_corrected.png` | 负向高斯修正后的概率场 |

可以额外做一个 **Streamlit 回放器** 或生成 **MP4 动画**，让你拖进度条看每步发生了什么。

**关键实现难点**：YOLO-World/GroundedSAM 推理速度。建议先用 YOLO-World（快，~30ms/帧）而非 SAM2（慢，~200ms/帧）。

### 2. 真机部署策略

真机部署的核心差异在于感知和定位：

| 仿真环境 | 真机 |
|----------|------|
| GT semantic sensor | RGB-D 相机 + 检测模型 |
| sim.pathfinder (perfect navmesh) | ROS nav_stack (SLAM + 局部规划) |
| 完美定位 | ORB-SLAM3 / RTAB-Map / LiDAR SLAM |
| 完美导航 | move_base + costmap |

**建议的最小真机架构** (基于你们组的 Fetch robot + osmAG-LLM 已有代码)：

```
Fetch Robot (ROS)
├── 感知: camera → YOLO-World → 3D投影 → Object
│         (复用 Phase 1 的感知管道)
├── 定位: ORB-SLAM3 或 RTAB-Map → agent 位姿
├── 建图: occupancy_grid → ROS costmap 或离线 pgm2osm
├── 导航: move_base → frontier_exploration_step 输出的目标点
└── AgenticRAG 核心: 完全复用 (map_Update, GMM, CLIP_RAG)
```

你们 `osmAG-LLM/fetch_nav/` 里已经有 `adjust_goal.py` `call_step_fun.py`，可以直接改造为 AgenticRAG 的执行层。

**建议先不急真机部署**。Phase 1 的 Sim2Sim 做好后，真机只是把 Habitat 的 observe() 替换为 ROS topic subscriber，核心算法完全不变。

### 3. 长期导航 Benchmark

这是**论文的核心创新点**——据我所知确实没有现成的 benchmark 评测"长期语义变化下的导航"。

**Benchmark 设计方案**：

```
LongNav-HM3D Benchmark
│
├── 数据层: N 个 HM3D 场景 × T 个时间点 (epoch)
│   每个 epoch 包含:
│   ├── 环境变化脚本 (物体增删/移动/状态变化)
│   ├── GT 语义地图 (真实物体位置)
│   └── 导航任务 (target object + start position)
│
├── 变化分级:
│   Level 1: 静态 (baseline, 等价于 ObjectNav)
│   Level 2: 小位移 (椅子推开/杯子换位)
│   Level 3: 大变化 (家具搬走/新物体出现)
│   Level 4: 语义变化 (电视开/关, 门开/关)
│
├── 评测指标:
│   ├── SPL (Success weighted by Path Length) — 标准
│   ├── SR (Success Rate) — 标准
│   ├── Map Quality: IoU(predicted_map, GT_map) per epoch
│   ├── Adaptation Speed: 变化后多少步恢复到 SR > 0.8
│   ├── Memory Efficiency: 地图增长率 vs 实际物体数
│   └── 负向高斯消融: 有/无记仇机制的 SR 差异
│
└── 实现方式:
    ├── 方案A: Habitat + 场景编辑 API (不确定 HM3D 是否支持)
    ├── 方案B: 多时间点独立场景 (每个 epoch 一个变体 .glb)
    └── 方案C: 脚本化地图扰动 (已有 make_t2_perturbed_map.py!)
```

**可行性分析**：

- **方案 B + C 结合最可行**：用你们已有的 `make_t2_perturbed_map.py` 脚本化地图变化 (物体增删/位移/label 变更)，每个 epoch 生成一个扰动地图。Habitat 仿真用同一个 .glb 但在感知层"信任"扰动后的地图。
- HM3D 有 **216 个场景** (80 train + 20 val + 18 minival...)，选 20-30 个多样场景即可。
- 每个场景生成 5 个 epoch，20 个 ObjectNav 任务/epoch → **3000 个测试实例**，足以发 benchmark paper。

**公布需要准备**：
1. 场景选择标准 + 变化生成脚本 + 配置文件
2. 评测代码 (evaluate.py)
3. 各 baseline 的复现结果 (ObjectNav baseline / static map / our full system)
4. 公开数据格式文档

### 4. 消融实验

基于现有系统，可以做以下消融：

| 实验 | 变量 | 预期效果 |
|------|------|----------|
| **A: ±负向高斯核** | `NegativeGaussianField` ON/OFF | OFF 时卡点，SR 大幅下降 |
| **B: ±时间衰减** | `virtual_clock` enabled/disabled | OFF 时过时信息占主导，变化场景 SR 下降 |
| **C: ±visit density** | visit_density 惩罚 ON/OFF | OFF 时重复探索同一区域 |
| **D: ±CLIP 检索** | 随机选物体 vs CLIP 语义匹配 | 无 CLIP 时候选数爆炸，precision 下降 |
| **E: ±Frontier 兜底** | flatness detection ON/OFF | OFF 时概率平原时无探索驱动 |
| **F: σ_neg 比例** | σ_neg/σ_base = 1.0 / 2.0 / 3.0 | 太小惩罚不够，太大误杀邻近真实位置 |
| **G: ±Agent Rscore (LLM)** | Rscore=0 vs Qwen 推理 | 有 LLM 时相关物体评分更准 |

**实现方式**：在 sim_nav_loop.py 加 `--ablation` flag：

```bash
python scripts/sim_nav_loop.py --target chair --ablation no_neg_gaussian
python scripts/sim_nav_loop.py --target chair --ablation no_time_decay
python scripts/sim_nav_loop.py --target chair --ablation no_visit_penalty
```

每个消融在 benchmark 的全部任务上跑一遍，统计 SR/SPL/探索效率，画表格。

### 建议优先级

```
Phase 1: Sim2Sim 视觉感知 + 多视角         ← 下一步 (堵住仿真到真机的最大 gap)
Phase 2: Benchmark 脚本化环境变化           ← 并行进行 (make_t2_perturbed_map 改造)
Phase 3: 消融实验框架 (加 --ablation)       ← Phase 1 完成后即可跑
Phase 4: 真机部署                          ← 最后 (Phase 1 做好后改动很小)
```
