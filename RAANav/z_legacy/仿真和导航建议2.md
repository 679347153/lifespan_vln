
## 我的理解

你的项目定位非常清晰：**不是做导航算法，而是做长期环境认知记忆系统**。核心卖点是：

1. **显式 RAG 记忆** — 跨月级别的时间跨度（别人最多做几分钟的 episode）
2. **负向高斯 "记仇"** — 假阴性驱动的主动遗忘 + 重新搜索
3. **时间衰减 × 稳定性** — 学习用户习惯（杯子爱动、冰箱不爱动）
4. **自定义指标** — SSS / D-SR / HPC 等衡量 "脑力" 而非 "体力"

导航只是验证手段，不是贡献点。这决定了工程实现的优先级。

## 下一步执行方案

结合你的三份文档和参考代码，4 个方向的具体路径：

### 1. 仿真探索 + 可视化

参考价值最高的是 **BeliefMapNav**：它的 frontier + 信息增益机制正好填补我们 `frontier_exploration_step()` 的短板。但我们**不需要照搬它的完整策略**（那变成在导航上卷了），只需要借鉴两点：

- **Frontier 检测**：从占据栅格自动提取已探索/未探索边界点（替代我们的 random fallback）
- **多朝向观测**：每步 4 个方向旋转 → 全景拼接（解决漏物体问题）

感知链路改造的最小路径如下：

```
当前: GT semantic sensor → AABB → Object
 ↓
Phase 1: RGB-D + 4方向旋转 → YOLO-World 开放词汇检测
         → depth 反投影 3D 位置 → Object → merge
         (仿真中, Habitat 已有 rgb+depth sensor)
```

可视化直接融入 sim_nav_loop.py 的每步循环：每步保存 `rgb.png` / `depth_colorized.png` / `detection_overlay.png` / `map_snapshot.png`，最后生成 MP4 回放。

### 2. 真机部署

你的感知定位方案（三阶段：结构拓扑粗配准 → 语义验证 → TEASER++ 精配准）设计得很扎实，和我们的地图结构天然契合：

| 你的三阶段 | 对应我们的模块 |
|-----------|--------------|
| 结构拓扑粗配准（墙/空间） | Floor + Room 层级 |
| 语义直方图验证 | Room.objects 的 label 分布 |
| 稳定物体质心 TEASER++ | Object.pos_3d + stability 过滤 |

但**现阶段不需要实现**。Phase 1 仿真做好后，真机只是把 `HabitatAgent.observe()` 替换为 ROS subscriber + 你的重定位模块。建议先写一个**接口定义**（抽象类），确保仿真和真机可以无缝切换。

### 3. Benchmark

最可行的路径是**方案 C（脚本化地图扰动）+ 你的自定义指标**：

```
LongNav Benchmark 生成流程:
  base_map.json (离线建图, 262 objects)
    │
    ├── make_epoch.py (改造自 make_t2_perturbed_map.py)
    │   epoch 1 (day 1):  原始地图
    │   epoch 2 (day 7):  移动 5 个低稳定性物体
    │   epoch 3 (day 14): 移动 10 个 + 删除 2 个 + 新增 3 个
    │   epoch 4 (day 30): 大变化 (家具重排)
    │
    ├── 每个 epoch × 20 个 ObjectNav 任务
    │   ├── 静态物体目标 (冰箱/沙发)  → Static-SR
    │   └── 动态物体目标 (杯子/椅子)  → Dynamic-SR (D-SR)
    │
    └── 评测: SSS, GHR@K, D-SR, HPC, FR-Acc
```

关键是：**不需要 Habitat 渲染每个变体场景**。地图扰动在 JSON 层面完成，仿真仅用原始 .glb 做物理导航，但感知层 "看到" 的物体位置取自扰动后的地图。这样工程量极小。

### 4. 消融实验

直接在 sim_nav_loop.py 加 `--ablation` flag，控制各模块的开关：

| Flag | 关闭什么 | 验证什么 |
|------|---------|---------|
| `no_neg_gaussian` | NegativeGaussianField 全部跳过 | 负向高斯核的效果（已有 baseline 对比数据） |
| `no_time_decay` | virtual_clock 不推进 / G_ts=1.0 | 时间衰减对动态物体的贡献 |
| `no_visit_penalty` | visit_density 置零 | 访问惩罚 vs 纯 GMM |
| `no_clip` | CLIP 检索替换为全物体 | CLIP 语义过滤的精度贡献 |
| `no_frontier` | 平坦检测关闭, 永远 GMM 模式 | Frontier 兜底的必要性 |
| `oracle_perception` | 保持 GT sensor | 感知噪声对上层系统的影响 |
